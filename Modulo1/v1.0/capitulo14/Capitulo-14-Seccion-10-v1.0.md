# Síntesis del capítulo

A lo largo de este capítulo analizamos escenarios provenientes de
distintos sectores:

-   asistentes corporativos;
-   desarrollo de software;
-   automatización documental;
-   analítica sobre Data Warehouse;
-   salud;
-   administración pública;
-   servicios financieros.

Aunque las tecnologías utilizadas fueron similares, las decisiones
arquitectónicas variaron significativamente debido a las características
particulares de cada dominio.

Esta observación constituye una de las principales enseñanzas del
capítulo.

No existen arquitecturas universales.

Existen principios que deben adaptarse cuidadosamente a cada contexto.

# Checklist para evaluar un nuevo proyecto

Antes de iniciar una iniciativa basada en Inteligencia Artificial, un
arquitecto puede utilizar el siguiente conjunto de preguntas.

  Pregunta                                             Estado
  --------------------------------------------------- --------
  ¿El problema de negocio está claramente definido?      □
  ¿La IA aporta valor demostrable?                       □
  ¿Los datos poseen la calidad necesaria?                □
  ¿Se identificaron riesgos y restricciones?             □
  ¿Existe una estrategia de evaluación?                  □
  ¿La solución contempla operación y monitoreo?          □
  ¿Se planificó la mejora continua?                      □

``` mermaid
mindmap
  root((Arquitectura IA))
    Negocio
    Datos
    Modelo
    Seguridad
    Operación
    Observabilidad
    Evolución
```

# Lo que un arquitecto debería recordar

-   Toda solución comienza comprendiendo el problema.
-   Las decisiones deben justificarse mediante evidencia.
-   La IA complementa procesos existentes; rara vez los reemplaza por
    completo.
-   El éxito depende tanto de la arquitectura como del modelo utilizado.
-   La mejora continua forma parte del ciclo de vida de cualquier
    solución inteligente.
