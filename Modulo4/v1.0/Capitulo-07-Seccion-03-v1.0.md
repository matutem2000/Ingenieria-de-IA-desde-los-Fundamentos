# Módulo 4 – Capítulo 07 – Sección 03

## Seguridad de Datos

Los datos de un sistema de IA son su activo más valioso y, con frecuencia, su mayor superficie de riesgo. La base vectorial contiene representaciones numéricas del conocimiento de la organización; los documentos indexados pueden incluir contratos, datos de clientes, información financiera y propiedad intelectual; el historial de conversaciones contiene las preguntas que los usuarios han hecho sobre temas sensibles. Cada uno de estos almacenes de datos requiere un modelo de seguridad específico que contemple no solo el cifrado en reposo y en tránsito, sino el control de acceso a nivel de dato, la detección de exfiltración y el cumplimiento de las regulaciones de protección de datos aplicables.

**Clasificación de datos antes de la indexación** es el primer control que el pipeline de ingesta debe implementar. No todos los documentos tienen el mismo nivel de sensibilidad, y no todos los usuarios del sistema deben poder acceder a todos los documentos indexados. El pipeline de ingesta debe clasificar automáticamente cada documento según su nivel de confidencialidad (público, interno, confidencial, secreto) y asignar esa clasificación como metadato al vector almacenado. La clasificación puede realizarse mediante un clasificador LLM que evalúa el contenido del documento, mediante reglas basadas en la fuente de origen del documento, o mediante etiquetas explícitas del sistema de gestión de contenidos de origen. Esta clasificación es la base para el control de acceso en la recuperación.

**Control de acceso a nivel de vector** es la capacidad de la base vectorial de filtrar los resultados de búsqueda según el nivel de autorización del usuario que realiza la consulta. Las principales bases vectoriales de producción — Pinecone, Weaviate y Qdrant — soportan filtrado por metadatos que puede usarse para implementar RBAC (Role-Based Access Control) en la recuperación: un usuario del departamento de ventas solo puede recuperar documentos etiquetados con los niveles de acceso que su rol tiene autorizado. Este control debe implementarse en la capa de la aplicación que construye la consulta al vector store, no solo en el LLM — confiar en que el modelo "sabrá" no revelar información sensible no es un control de seguridad válido.

**Cifrado en reposo y en tránsito** son los controles de seguridad más estándar y los primeros en implementarse. La base vectorial, los documentos de fuente y el almacenamiento de historial de conversaciones deben estar cifrados en reposo usando estándares actuales (AES-256). Las comunicaciones entre todos los componentes del sistema — aplicación, base vectorial, LLM API, almacenamiento de documentos — deben usar TLS 1.2 o superior. En sistemas cloud, esto es frecuentemente el comportamiento por defecto, pero debe verificarse explícitamente para cada servicio utilizado.

**Gestión de datos personales en sistemas RAG** es un área donde el cumplimiento de GDPR (en la Unión Europea) y CCPA (en California) impone requisitos específicos. Si los documentos indexados contienen datos personales identificables — emails de clientes, contratos con nombres, registros de empleados — el sistema debe implementar mecanismos para: detectar y etiquetar esos datos en el momento de la indexación, soportar el derecho de supresión (poder eliminar todos los vectores que provienen de documentos relacionados con un individuo específico), y documentar qué datos personales están almacenados y por qué (el registro de actividades de tratamiento requerido por GDPR). La supresión de vectores es operacionalmente compleja si los documentos no están correctamente identificados en el momento de la indexación: retrofitar el control de privacidad después del hecho requiere re-indexar toda la base de conocimiento.

**Retención y purga de datos de conversación** es otro requisito de privacidad específico de sistemas de IA. El historial de conversaciones — las preguntas que el usuario hizo, el contexto que recibió, las respuestas que generó el sistema — contiene información potencialmente sensible sobre los intereses, preocupaciones y actividad del usuario. La política de retención de estos datos debe estar definida antes del despliegue: cuánto tiempo se conservan, con qué granularidad (completos vs. anonimizados), quién puede acceder, y cuál es el proceso de eliminación ante una solicitud del usuario.

**Detección de exfiltración de datos** es el control que detecta cuando el sistema está siendo utilizado para extraer información de la base de conocimiento de manera no autorizada. Un usuario que realiza cientos de consultas sistemáticas diseñadas para extraer el contenido completo de documentos específicos está atacando el sistema aunque cada consulta individual sea aparentemente legítima. Patrones de consultas anómalos — volumen inusual, consultas muy específicas sobre entidades concretas, consultas que parecen explorar sistemáticamente el espacio de documentos — deben generar alertas para revisión humana.

La seguridad de datos en sistemas de IA no puede delegarse completamente a los controles del proveedor de infraestructura. El arquitecto es responsable de diseñar los controles específicos que protegen los datos en función de su sensibilidad, del contexto regulatorio y del perfil de usuarios del sistema.
