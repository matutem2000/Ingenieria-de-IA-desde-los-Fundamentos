# Módulo 4 – Capítulo 07 – Sección 04

## Control de Acceso

El control de acceso en sistemas de IA modernos debe extenderse significativamente más allá del control de acceso al endpoint de la aplicación. Un sistema de IA típico tiene múltiples superficies de acceso: la API del modelo de lenguaje, la base vectorial, el almacenamiento de documentos, las herramientas que los agentes pueden invocar, el sistema de administración del pipeline, y los dashboards de observabilidad. Cada una de estas superficies debe tener su propio modelo de control de acceso, y todos deben estar coordinados por una estrategia de identidad coherente.

**Autenticación de la API de LLM** es el control más básico pero con implicaciones de costo significativas. Las claves de API de proveedores como OpenAI, Anthropic o Google son credenciales que, si se comprometen, permiten al atacante realizar llamadas ilimitadas al modelo a costo del propietario de la clave. Las mejores prácticas incluyen: uso de claves de API con scopes limitados (si el proveedor lo soporta), rotación periódica de claves, almacenamiento de claves en sistemas de gestión de secretos (AWS Secrets Manager, HashiCorp Vault, Azure Key Vault) — nunca en repositorios de código o variables de entorno en texto claro —, y límites de gasto configurados en el dashboard del proveedor que generen alertas o corten el acceso si se supera el presupuesto.

**Control de acceso a la base vectorial** debe implementarse en dos niveles. El primer nivel es el acceso a la infraestructura: quién puede conectarse a la base vectorial, con qué credenciales, y desde qué redes. Las bases vectoriales en producción deben estar en redes privadas, no expuestas a internet, accesibles solo desde los servicios autorizados del sistema. El segundo nivel es el acceso a nivel de dato: como se describió en la sección anterior, el filtrado por metadatos de clasificación de datos debe implementarse en cada consulta. Un servicio de recuperación no debe poder acceder a datos que el usuario que lo invoca no está autorizado a ver.

**Control de acceso a herramientas en sistemas de agentes** es el aspecto más crítico y menos estándar del control de acceso en sistemas de IA. Cada herramienta que un agente puede invocar es un punto de acceso a un sistema externo: una base de datos, una API de terceros, un sistema de envío de emails, o el sistema de archivos. El principio de mínimo privilegio debe aplicarse explícitamente a cada herramienta: la herramienta de búsqueda en base de datos solo tiene credenciales de lectura, no de escritura; la herramienta de envío de emails solo puede enviar a dominios de la lista blanca configurada; la herramienta de ejecución de código opera en un sandbox sin acceso a la red y sin capacidad de escribir en directorios críticos del sistema.

**Identidad de los agentes** es un problema emergente en sistemas multiagente. Cuando un agente delega una subtarea a otro agente, ¿con qué identidad opera el segundo agente? ¿Con la identidad del usuario original? ¿Con su propia identidad de servicio? ¿Con los permisos del agente orquestador? La decisión tiene consecuencias de seguridad significativas. La práctica recomendada es la propagación controlada de la identidad del usuario original con reducción de privilegios: el agente delegado opera con los permisos del usuario original o con menos permisos, nunca con más.

**Separación de roles administrativos** en el sistema de IA incluye: quién puede actualizar el system prompt (privilegio crítico que equivale a modificar la lógica de negocio del sistema), quién puede añadir o eliminar documentos de la base de conocimiento, quién puede cambiar los modelos o la configuración del pipeline, y quién puede acceder a los logs de conversaciones. Estos roles deben ser distintos y asignados con el mismo rigor que los roles de administración de bases de datos de producción.

**Autenticación de usuarios en sistemas multi-tenant** requiere que cada consulta que llega al sistema de IA esté asociada a un usuario autenticado, y que esa identidad se propague a través de todas las capas del sistema para el filtrado de datos. Los tokens JWT, OAuth 2.0 y OIDC son los estándares de autenticación más utilizados. La verificación del token debe ocurrir en el gateway de entrada al sistema, no en el LLM o en la base vectorial — ningún componente downstream debe confiar en que la autenticación fue verificada por un componente upstream.

El control de acceso en sistemas de IA no es diferente en sus principios fundamentales del control de acceso en cualquier sistema empresarial: autenticación robusta, autorización granular basada en roles, principio de mínimo privilegio, auditoría de accesos. Lo que es específico de los sistemas de IA es el número y la variedad de las superficies de acceso, y la necesidad de propagar la identidad del usuario a través de componentes que históricamente no tenían ese concepto: los modelos de lenguaje y las bases vectoriales.
