# Módulo 7 – Capítulo 05 – Sección 05

## Criterios de selección de framework: complejidad, control y observabilidad

Haber estudiado cuatro frameworks —LangGraph, AutoGen, CrewAI, Pydantic AI— genera una pregunta práctica que ningún tutorial responde bien: ¿cómo se elige el correcto para un proyecto específico? La respuesta no es una clasificación de popularidad ni una comparación de GitHub stars. Es un análisis de tres dimensiones que el proyecto requiere concretamente: la complejidad del flujo de control, el nivel de control y determinismo necesario, y las capacidades de observabilidad disponibles. Un framework seleccionado sin este análisis produce dos tipos de problemas igualmente costosos: elegir uno demasiado simple para el caso de uso (se choca con las limitaciones del framework cuando el agente crece en complejidad), o elegir uno demasiado poderoso (overhead de abstracción innecesario que ralentiza el desarrollo y complica el debugging para un caso de uso que no lo justifica).

**LangGraph** es la elección correcta cuando el flujo de control del agente requiere ciclos, paralelismo, o subgrafos, o cuando la trazabilidad de cada transición de estado es un requisito de auditoría o compliance. Un agente de aprobación de créditos que puede regresar a pasos anteriores para solicitar documentación adicional, que ejecuta múltiples verificaciones en paralelo, y que debe mantener un log auditable de cada decisión tomada es un caso perfecto para LangGraph. La curva de aprendizaje es alta —el modelo mental de grafos de estado es diferente al de código secuencial— y el overhead de configuración para casos simples puede ser excesivo. No elegir LangGraph cuando el flujo es lineal y sin ciclos; para esos casos, AutoGen, CrewAI o directamente la API del proveedor son más apropiados.

**AutoGen** es la elección correcta cuando el patrón central del agente es generación-ejecución iterativa de código Python, o cuando se necesita orquestar múltiples LLMs en conversación donde la flexibilidad del diálogo entre agentes es más importante que el control del flujo. Un agente de análisis exploratorio de datos donde el investigador escribe código de análisis, el ejecutor lo ejecuta, y el analista interpreta los resultados en un flujo conversacional libre es el caso de uso donde AutoGen es naturalmente superior. No elegir AutoGen cuando se necesita determinismo estricto en el flujo o cuando el debugging sistemático de la secuencia de acciones es crítico.

**CrewAI** es la elección correcta cuando la velocidad de desarrollo es la prioridad y el equipo no tiene experiencia profunda en frameworks agénticos, el flujo es secuencial o jerárquico con roles bien definidos, y los casos de uso son suficientemente estándar para que las abstracciones de alto nivel de CrewAI sean una ventaja. Para un MVP de un sistema de generación de contenido donde un agente investiga, uno redacta, uno revisa y uno publica, CrewAI permite tener el sistema funcionando en horas en lugar de días. No elegir CrewAI para sistemas de producción que requieren control fino sobre la lógica de coordinación o cuando los casos de borde del flujo son complejos.

**Pydantic AI** es la elección correcta cuando la validación de tipos de entrada/salida es crítica para la integridad del sistema, el agente se integra directamente con código Python que consume su output como objetos tipados, y el equipo tiene experiencia en tipado estático con Python. Para agentes que alimentan APIs, pipelines de procesamiento de datos, o sistemas donde un output mal formado produce fallos difíciles de diagnosticar, Pydantic AI provee garantías que ningún otro framework da. No elegir Pydantic AI como alternativa a LangGraph para flujos de control complejos; son frameworks con fortalezas complementarias, no alternativas directas.

La **opción sin framework** —usar function calling directo de la API del proveedor con código Python— es la más frecuentemente olvidada y una de las más correctas para un espacio relevante de casos de uso. Para agentes con 1-3 herramientas, flujo lineal sin ciclos, y sin requisitos de checkpointing o multi-agente, el código resultante usando directamente la API de OpenAI o Anthropic es más simple, más rápido de depurar, más fácil de mantener y más predecible que cualquier framework. El costo de adoptar un framework es real: curva de aprendizaje, debugging a través de capas de abstracción, actualizaciones de versión con breaking changes. Este costo solo se justifica cuando el caso de uso supera las capacidades del enfoque más simple.

## Conceptos clave

- **LangGraph**: flujo complejo con ciclos, paralelismo, subgrafos; auditoría de cada transición; human-in-the-loop con checkpointing; curva de aprendizaje alta; no usar para flujos lineales simples
- **AutoGen**: generación-ejecución iterativa de código; orquestación conversacional multi-LLM; no usar cuando se requiere determinismo estricto del flujo o debugging sistemático de la secuencia de acciones
- **CrewAI**: velocidad de desarrollo como prioridad; flujos secuenciales o jerárquicos con roles estándar; no usar para sistemas de producción con lógica de coordinación compleja o casos de borde no estándar
- **Pydantic AI**: validación de tipos de output como garantía de confiabilidad; integración con código Python tipado que consume directamente el output del agente; complementa LangGraph, no lo reemplaza
- **Sin framework (API directo)**: la opción más simple y frecuentemente la más correcta para agentes con 1-3 herramientas y flujo lineal; menor overhead, código más legible, menor costo de mantenimiento

> **Nota del Arquitecto**: La presión del equipo para adoptar el framework más popular o el más sofisticado es real pero contraproductiva. He visto proyectos que implementaron LangGraph para un agente de 2 herramientas con flujo lineal, produjeron código difícil de leer para los stakeholders, y tuvieron bugs de versión que tardaron días en diagnosticar. La misma funcionalidad implementada directamente con la API de Anthropic habría sido 5 veces menos código y depurable en minutos. El mejor framework es el mínimo suficiente para el problema, evaluado honestamente contra el caso de uso real, no contra el caso de uso más sofisticado que se podría imaginar.

## Para recordar

El mejor framework de agentes para un proyecto es el mínimo necesario para resolver el problema: empezar con la API directa del proveedor y agregar el framework solo cuando el caso de uso supera las capacidades del approach más simple. Esta regla previene el sobrediseño y mantiene el código legible para el próximo desarrollador que lo va a leer.
