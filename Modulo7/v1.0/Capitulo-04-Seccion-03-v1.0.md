# Módulo 7 – Capítulo 04 – Sección 03

## Memoria de largo plazo: almacenamiento persistente y recuperación selectiva

La memoria de corto plazo tiene una duración de una sesión: cuando la conversación termina, el contexto se pierde. La memoria de largo plazo extiende el horizonte temporal del agente indefinidamente: información de sesiones pasadas, preferencias del usuario desarrolladas a lo largo de semanas de interacciones, hechos del dominio aprendidos en tareas anteriores, y errores cometidos que no deben repetirse. Sin este mecanismo, cada sesión del agente es estadísticamente idéntica a la primera: el sistema no puede personalizar, no puede mejorar, y no puede construir sobre el contexto acumulado de relaciones largas con usuarios o dominios complejos.

La implementación técnica de la memoria de largo plazo combina dos componentes: **almacenamiento persistente** para guardar las memorias de forma durable entre sesiones, y **recuperación selectiva** para decidir qué subset de la memoria disponible es relevante para la tarea actual. El almacenamiento puede ser relacional (PostgreSQL para datos estructurados con metadata compleja), documental (MongoDB para memorias de formato variable), o de baja latencia (Redis para cache de acceso frecuente). El schema mínimo recomendado para cada unidad de memoria incluye: `id`, `user_id`, `session_id`, `timestamp`, `content` (el texto de la memoria), `type` (categoría: preferencia, hecho, error, decisión), `embedding` (el vector para recuperación semántica), y `metadata` (campos adicionales para filtrado: dominio, importancia, expiración). El campo `type` es especialmente importante: permite filtrar memorias por categoría antes de la búsqueda semántica, reduciendo el espacio de recuperación y mejorando la precisión.

La **recuperación selectiva** es el componente que determina la utilidad práctica del sistema de memoria. No toda la memoria disponible es relevante para cada nueva sesión: recuperar todo generaría contextos enormes que consumen la ventana disponible con información mayoritariamente irrelevante. Los criterios de recuperación efectiva combinan múltiples dimensiones: **recencia** (las últimas N sesiones del usuario tienen mayor probabilidad de ser relevantes), **relevancia semántica** (los ítems de memoria más similares semánticamente a la query o el objetivo de la sesión actual), e **importancia** (ítems marcados explícitamente como high-priority, como preferencias establecidas o errores críticos identificados). El retrieval híbrido que combina filtrado por metadata (user_id, date_range, type) con búsqueda semántica produce mejores resultados que cualquiera de los dos mecanismos por separado.

El **trigger de escritura en memoria** determina cuándo el agente almacena nueva información. Hay tres estrategias con diferentes trade-offs. La escritura al final de sesión (batch write) es la más simple: al cerrar una conversación, el agente o un proceso separado analiza toda la sesión y extrae lo que vale la pena recordar. La escritura selectiva durante la sesión (selective write) permite al agente identificar y almacenar información importante en tiempo real —"el usuario acaba de mencionar que prefiere respuestas en inglés"— usando una herramienta de escritura en memoria que el agente puede invocar cuando identifica información relevante. La escritura basada en reglas aplica criterios programáticos: si el usuario especifica explícitamente una preferencia, si el agente cometió un error y fue corregido, si se aprendió un hecho nuevo sobre el dominio, almacenar automáticamente. En la práctica, la combinación de escritura basada en reglas para información estructurada y escritura selectiva para información no estructurada produce los mejores resultados.

El **aislamiento por user_id** es un requisito no negociable de privacidad. La memoria de largo plazo de un usuario no debe ser accesible para ningún otro usuario, y un bug de filtrado que exponga memorias de un usuario a otro es una vulnerabilidad de privacidad crítica. Este filtrado debe implementarse a nivel de query de base de datos —`WHERE user_id = :current_user_id` en cada consulta— no solo a nivel de aplicación, para garantizar que ningún bug en la lógica de la aplicación pueda bypassear la restricción.

Sistemas como **MemGPT** (ahora renombrado como Letta) implementan este patrón con una arquitectura donde el agente tiene acceso a herramientas de lectura y escritura en su propia memoria de largo plazo: el agente puede invocar `memory.read(query)` para recuperar memorias relevantes y `memory.write(content, type)` para almacenar nueva información durante la ejecución. Este diseño convierte la gestión de memoria en una capacidad de primer nivel del agente, no en un proceso externo que ocurre sin el conocimiento del modelo.

## Aspectos técnicos

- **Schema de memoria persistente**: estructura mínima `{id, user_id, session_id, timestamp, content, type, embedding, metadata}`; el campo `type` permite filtrado por categoría antes de la búsqueda semántica; el campo `embedding` habilita recuperación semántica
- **Write trigger strategies**: escritura al final de sesión (simple), escritura selectiva durante la sesión (el agente usa una herramienta de escritura cuando identifica información importante), escritura basada en reglas (automática para categorías predefinidas como preferencias y errores); combinar las tres estrategias
- **Recuperación híbrida**: combinar filtrado por metadata (user_id, date_range, type) con búsqueda semántica (top-k por similaridad coseno del embedding); el filtrado reduce el espacio de búsqueda, la semántica optimiza la relevancia dentro de ese espacio
- **Memory decay con TTL**: implementar expiración para memorias que pierden relevancia con el tiempo; preferencias de UI del usuario pueden expirar en 30 días, hechos de dominio pueden ser permanentes; configurar TTL por categoría de memoria
- **Aislamiento por user_id**: filtrado a nivel de query de base de datos (`WHERE user_id = :current_user_id`) en cada operación de recuperación; nunca delegar el aislamiento únicamente a la lógica de aplicación

## Principio rector

La memoria de largo plazo transforma cada nueva sesión del agente de una interacción sin contexto previo a una conversación que construye sobre el historial acumulado; pero ese poder requiere controles estrictos de privacidad, relevancia y expiración para no degradar la calidad con información obsoleta o irrelevante que contamina el razonamiento.
