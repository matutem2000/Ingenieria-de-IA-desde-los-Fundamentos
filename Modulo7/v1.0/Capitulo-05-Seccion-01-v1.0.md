## LangGraph: grafos de estado para flujos agénticos deterministas y cíclicos

El capítulo anterior construyó los componentes internos del agente: razonamiento, herramientas, memoria. Este capítulo examina la infraestructura que organiza esos componentes en sistemas cohesivos y operables: los frameworks de agentes. LangGraph es el framework más adecuado cuando el flujo de control del agente es complejo —ciclos, paralelismo, subgrafos, interrupciones para revisión humana— y cuando la auditoría de cada transición de estado es un requisito operativo. Comprender LangGraph es comprender el enfoque de control máximo en la ingeniería agéntica moderna.

LangGraph es el framework de agentes de LangChain que modela el comportamiento agéntico como un grafo de estado explícito: cada nodo es una función Python que recibe el `AgentState` actual, lo procesa, y devuelve un nuevo estado; cada arista (directa o condicional) define las transiciones entre nodos. A diferencia del `AgentExecutor` de LangChain clásico —que usa un bucle while implícito difícil de inspeccionar y modificar—, LangGraph expone el grafo completo del agente como un objeto que puede ser visualizado, compilado, y ejecutado con control preciso sobre cada transición. Un grafo de LangGraph es directamente legible como arquitectura: se puede ver exactamente qué nodos existen, qué condiciones determinan cada transición, y cuáles son los estados terminales posibles.

El componente central es el **`StateGraph` con su `AgentState`**. El estado se define como un `TypedDict` con los campos que deben persistir entre nodos: historial de mensajes, variables de contexto de la tarea, resultados intermedios, contadores de iteración. Cada campo puede tener una función de reducción que define cómo se combina el nuevo valor con el valor anterior: por defecto, el nuevo valor reemplaza al anterior; para listas como el historial de mensajes, la reducción habitual es concatenar (añadir los nuevos mensajes al historial existente). Los nodos se registran con `graph.add_node(name, function)` y las aristas con `graph.add_edge(from_node, to_node)` para aristas directas o `graph.add_conditional_edges(from_node, condition_fn, {outcome: next_node})` para aristas condicionales. La `condition_fn` inspecciona el estado actual y devuelve la clave del próximo nodo.

Las **aristas condicionales** son la característica que hace a LangGraph fundamentalmente diferente de un pipeline secuencial. En un agente ReAct implementado en LangGraph, la arista condicional desde el nodo de razonamiento determina si el agente debe invocar una herramienta (el LLM decidió hacer una tool call) o terminar (el LLM decidió dar la respuesta final al usuario). Esta condición no está hardcodeada en la lógica del agente; está representada como una función Python en el grafo que es auditable, testeable de forma independiente, y modificable sin tocar el resto del flujo. Esta separación entre el flujo de control y la lógica de cada nodo es la propiedad más valiosa de LangGraph para sistemas de producción que evolucionan.

El **checkpointing** es la función que transforma LangGraph de un framework de agentes a un sistema de agentes stateful en producción. Al compilar el grafo con `graph.compile(checkpointer=SqliteSaver.from_conn_string("agents.db"))` y ejecutar con un `thread_id` específico, LangGraph serializa el `AgentState` completo a la base de datos después de cada nodo. Esto permite: reanudar sesiones interrumpidas exactamente desde el último nodo completado, ejecutar múltiples sesiones concurrentes del mismo agente con estado independiente, y hacer debugging reproduciendo la ejecución desde cualquier estado guardado. En producción con `PostgresSaver`, el checkpointing provee la misma garantía con alta disponibilidad y sin el límite de escala de SQLite.

El **streaming de pasos** con `graph.stream(input, config)` devuelve un generador que emite el estado después de cada nodo, permitiendo que el cliente vea el progreso del agente en tiempo real. Esto es fundamentalmente diferente a esperar el resultado final: el usuario puede ver "Buscando información... Analizando resultados... Generando respuesta..." en lugar de una pantalla en blanco durante los 30 segundos que tarda la tarea. El **Human-in-the-Loop nativo** se implementa con `interrupt_before` e `interrupt_after`: el grafo se pausa antes o después de nodos específicos, persiste el estado, y espera que el operador humano apruebe la acción con `graph.invoke(Command(resume=value), config)` o la rechace. Esta funcionalidad es la base de los patrones de revisión humana que el Capítulo 08 examinará en el contexto de seguridad agéntica.

## Componentes principales

- **StateGraph y AgentState**: el grafo se define tipando el estado con `TypedDict` (campos con funciones de reducción configurables) y registrando nodos con funciones Python que reciben y devuelven el estado
- **Aristas condicionales**: `add_conditional_edges(node, condition_fn, {outcome: next_node})` permite routing dinámico basado en el estado actual; la condition_fn es una función Python auditable y testeable independientemente
- **Checkpointing**: `MemorySaver` (en memoria, para tests), `SqliteSaver` (desarrollo local), `PostgresSaver` (producción con alta disponibilidad); persiste el estado después de cada nodo; habilita reanudación de sesiones interrumpidas
- **Streaming de pasos**: `graph.stream()` emite el estado después de cada nodo; permite mostrar el progreso del agente en tiempo real en el UI; fundamental para tareas que tardan más de 10 segundos
- **Human-in-the-loop nativo**: `interrupt_before=["node_name"]` y `interrupt_after=["node_name"]` pausan el grafo para revisión humana; reanudado con `Command(resume=value)`; el estado persiste en el checkpointer durante la pausa

> **Nota del Arquitecto**: La curva de aprendizaje de LangGraph es real: el modelo mental de grafos de estado es diferente al de código secuencial o al de pipelines de funciones. La inversión se justifica cuando el flujo del agente tiene ciclos, cuando necesitas human-in-the-loop con persistencia de estado, o cuando la trazabilidad de cada transición es un requisito de auditoría. Si el flujo es lineal y sin ciclos, considera si realmente necesitas LangGraph o si una cadena de funciones Python con checkpointing manual sería más simple y suficiente.

## Principio rector

LangGraph convierte el flujo de control del agente de un comportamiento emergente implícito a un grafo explícito e inspeccionable: cada decisión de routing es una función Python auditable, y cada estado intermedio puede ser persistido, reproducido y analizado. Esta explicitación del flujo de control es su diferenciador fundamental respecto a frameworks con abstracciones de mayor nivel.

La sección siguiente examina AutoGen, el framework de Microsoft Research que adopta un enfoque radicalmente diferente: en lugar de grafos de estado, modela la coordinación agéntica como conversaciones entre múltiples agentes con roles especializados.
