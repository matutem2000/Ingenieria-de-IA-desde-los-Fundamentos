# ReAct (Reason + Act): intercalar razonamiento con acciones externas

CoT mejora el razonamiento, pero razonar en el vacío tiene un límite fundamental: el modelo solo puede razonar sobre lo que ya sabe. Para tareas que requieren información actualizada, verificación factual, o acceso a datos externos, el razonamiento interno no es suficiente. ReAct es el patrón que resuelve esta limitación cerrando el bucle entre pensamiento y mundo real: el agente alterna explícitamente entre generar razonamiento y ejecutar acciones, usando los resultados de esas acciones para refinar su razonamiento en el paso siguiente.

ReAct fue presentado por Yao et al. (2022) en "ReAct: Synergizing Reasoning and Acting in Language Models" y demostró que la alternancia entre razonamiento (Thought) e invocación de acciones externas (Act) con retroalimentación de observaciones (Observation) produce resultados significativamente mejores que CoT puro en tareas que requieren acceso a información externa. La intuición del experimento es directa: en HotpotQA (un benchmark de preguntas que requieren múltiples pasos de búsqueda), ReAct supera a CoT porque puede corregir errores de razonamiento basándose en evidencia real en lugar de en inferencias. Si el agente busca "capital de Australia" y el resultado dice "Canberra", esa observación puede corregir el razonamiento previo que incorrectamente asumía "Sídney".

El formato Thought-Action-Observation que define el patrón ReAct opera de la siguiente manera en la práctica: el LLM genera primero un `Thought` en texto libre que articula el razonamiento sobre el estado actual y la siguiente acción a tomar ("Necesito verificar cuándo se fundó la empresa X para calcular su antigüedad. Usaré la búsqueda web con la query específica"). Luego genera un `Action` que especifica la herramienta y los argumentos (`search_web(query="Company X founding year")`). El sistema ejecuta la herramienta y devuelve el resultado como `Observation` ("Company X was founded in 1998 by..."). Este triplete Thought-Action-Observation se acumula en el contexto, y el LLM genera el siguiente Thought basándose en toda la evidencia acumulada. El ciclo continúa hasta que el agente tiene suficiente información para dar la respuesta final.

Este patrón es la base arquitectónica de la mayoría de frameworks agénticos modernos. LangChain AgentExecutor implementa directamente el formato Thought-Action-Observation. LangGraph con nodos de herramientas es una implementación de ReAct en forma de grafo de estado. El workflow `tool_use` de Anthropic, donde el modelo alterna entre generar bloques `text` y bloques `tool_use`, es ReAct bajo la nomenclatura de la API. OpenAI GPT-4o con function calling implementa el mismo patrón aunque no use la terminología explícita. La ubicuidad de ReAct en la práctica refleja su efectividad como patrón base para agentes que necesitan información del mundo real.

Hay un costo operativo que debe considerarse en el diseño. Cada iteración ReAct añade al contexto el Thought (50-200 tokens), la Action (20-100 tokens), y la Observation (variable, puede ser 500-2000 tokens para resultados de búsqueda web). En tareas de 10 pasos, esto puede acumular 5K-15K tokens solo en trazas de razonamiento e interacción con herramientas, antes de contabilizar el system prompt y el historial de la conversación. Esto tiene consecuencias en costo (más tokens = mayor costo de API) y en calidad (contextos más largos pueden sufrir del "lost-in-the-middle problem" que se desarrolla en el Capítulo 04). El diseño de cuánto razonamiento explicitar y cuánta observación incluir en cada paso es una variable de diseño que afecta tanto la calidad como el costo.

## Aspectos técnicos

- **Formato Thought-Action-Observation**: cada iteración del bucle acumula en el contexto el razonamiento explícito, la acción invocada y su resultado; este historial guía las decisiones de acción en todos los pasos posteriores
- **Grounding externo**: a diferencia de CoT puro, ReAct puede corregir errores de razonamiento basándose en evidencia real obtenida de herramientas, reduciendo alucinaciones en tareas que requieren información factual actualizada
- **Action space definition**: el conjunto de acciones disponibles (herramientas con nombre, descripción y schema) se inyecta en el system prompt; descripciones ambiguas degradan directamente la calidad de las decisiones de Action
- **Interleaving obligatorio**: el razonamiento y la acción deben alternarse en el mismo hilo de generación del LLM; separar ambas fases en llamadas distintas al modelo rompe la coherencia del razonamiento porque el contexto de la fase Think no está disponible en la fase Act
- **Overhead de tokens**: tareas de 10 pasos pueden consumir 5K-15K tokens en trazas de razonamiento + observaciones; este costo debe considerarse en el modelo de costos del agente antes del despliegue

> **Nota del Arquitecto**: El error más común con ReAct en producción es no limitar el tamaño de las Observations. Una búsqueda web que devuelve 10 resultados completos con 500 palabras cada uno puede añadir 5K tokens al contexto en un solo paso. La solución es doble: configurar la herramienta para devolver solo los primeros 200 caracteres por resultado, y añadir una instrucción explícita en el system prompt para que el agente sepa que puede invocar la herramienta nuevamente con una query más específica si los snippets no son suficientes.

## Para recordar

ReAct transforma al LLM de un sistema que razona en el vacío a uno que razona sobre evidencia real: cada observación de herramienta es información nueva que puede confirmar, refutar o redirigir el plan del agente. Esta capacidad de corrección basada en evidencia es la diferencia entre un agente que alucina con confianza y uno que verifica antes de responder.

La siguiente sección examina Tree of Thoughts, una extensión de ReAct que en lugar de seguir un camino lineal de razonamiento, explora múltiples caminos simultáneamente para encontrar la estrategia óptima en problemas de planificación complejos.
