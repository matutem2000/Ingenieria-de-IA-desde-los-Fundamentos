# Privacidad diferencial: procesar datos sensibles localmente, enviar datos genéricos a la nube

El patrón de privacidad diferencial en arquitecturas híbridas divide el pipeline de procesamiento según la sensibilidad de los datos: las partes del flujo que involucran información personal identificable (PII), datos regulados (HIPAA, GDPR, PCI-DSS) o información confidencial del negocio se ejecutan en el modelo local dentro del perímetro de seguridad de la organización, mientras que las partes que involucran información genérica o previamente anonimizada se pueden delegar a APIs de nube con los beneficios de modelos más capaces. Un ejemplo concreto de este patrón: en un asistente de atención médica, la extracción de entidades clínicas (nombres de medicamentos, diagnósticos, síntomas) se realiza localmente con un modelo fine-tuneado en datos médicos; el texto clínico anonimizado resultante (con PII substituida por tokens placeholder) se envía a la nube para síntesis de resumen clínico con un modelo de frontera; el resultado de la nube se postprocesa localmente para restaurar los valores reales de PII en el contexto adecuado. La técnica de anonimización estructurada (también llamada de-identification o text anonymization) usa herramientas como Presidio (Microsoft) o spaCy con entidades NER para detectar y sustituir automáticamente PII antes de enviar texto a la nube: `presidio_anonymizer.anonymize(text, analyzer_results)` reemplaza nombres, DNIs, emails, teléfonos y fechas con tokens de tipo `<PERSON_0>`, `<DATE_1>` que preservan la estructura gramatical del texto para que el modelo de nube pueda procesarlo correctamente.

## Implementación del patrón de privacidad diferencial

- Presidio para de-identification: librería de Microsoft diseñada específicamente para detección y anonimización de PII; soporta 20+ tipos de entidades predefinidas y entidades custom vía recognizers propios; usa spaCy + expresiones regulares + listas de entidades conocidas; disponible en Python y como servicio HTTP
- Tokenización reversible: para poder revertir la anonimización en la respuesta de la nube, se mantiene un mapa local `{token → valor_real}` asociado a la sesión de usuario; la respuesta de la nube que contiene `<PERSON_0>` se postprocesa localmente sustituyendo de vuelta por el nombre real antes de devolver al usuario
- Local inference para extracción de PII: el modelo local de extracción de PII puede ser un modelo BERT/RoBERTa de NER fine-tuneado en el dominio específico, más preciso que los sistemas de reglas generales de Presidio para jerga médica, legal o financiera; este modelo es el guardián del perímetro de privacidad
- Auditoría de flujo de datos: registrar (en logs locales, fuera del perímetro) qué datos se enviaron a la nube (solo los textos anonimizados), qué proveedor procesó la petición y cuándo; esta auditoría es el componente de compliance que demuestra que los datos sensibles nunca salieron del perímetro
- Evaluación de calidad con datos anonimizados: la calidad del modelo de nube sobre texto anonimizado puede ser diferente de su calidad sobre texto real (los tokens placeholder interrumpen la coherencia lingüística); evaluar explícitamente la calidad de las respuestas en datos anonimizados antes de adoptar el patrón en producción

## Para recordar

La privacidad diferencial en arquitecturas híbridas no es solo un requisito de compliance sino una ventaja competitiva: permite usar los mejores modelos de IA del mundo en datos sensibles que de otra forma solo podrían procesarse con modelos locales de menor capacidad.
