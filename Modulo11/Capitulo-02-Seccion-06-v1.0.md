# Módulo 11 – Capítulo 02 – Sección 06

# Cierre: una arquitectura de referencia enterprise reduce el tiempo de decisión de cada equipo

La arquitectura de referencia enterprise para IA cumple una función que va más allá de la documentación técnica: establece las decisiones de diseño ya tomadas por el equipo de plataforma, liberando a los equipos de producto de tener que resolver desde cero problemas ya resueltos como la selección de la base de datos vectorial, el modelo de autenticación, o la estrategia de observabilidad. Cada patrón cubierto en este capítulo — la arquitectura en capas, el modelo Hub-and-Spoke, el procesamiento orientado a eventos, el API management con versionado semántico, y las landing zones de IA — responde a una categoría de problema que invariablemente aparece cuando se escala de un piloto a un sistema enterprise operado por múltiples equipos sobre infraestructura compartida. La deuda técnica de arquitectura es la más cara en sistemas enterprise: tomar decisiones apresuradas de diseño en las fases tempranas de un proyecto puede requerir reescrituras completas meses después cuando el sistema ya está en producción y tiene integraciones activas que no pueden interrumpirse. Invertir en definir y documentar la arquitectura de referencia antes de que los equipos comiencen a construir es siempre más barato que refactorizar sistemas en producción con restricciones de disponibilidad.

*"La arquitectura no se trata de hacer las cosas correctamente la primera vez, sino de crear las condiciones para que el sistema pueda evolucionar cuando los requerimientos inevitablemente cambien."* — Martin Fowler, autor de "Patterns of Enterprise Application Architecture"
