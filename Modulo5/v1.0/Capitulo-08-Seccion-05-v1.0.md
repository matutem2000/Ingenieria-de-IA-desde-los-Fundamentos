# Módulo 5 – Capítulo 08 – Sección 05

## Herramientas: LangSmith, Langfuse, Weights & Biases y OpenTelemetry

El ecosistema de observabilidad para sistemas de IA ha madurado en los últimos dos años desde un vacío —donde los equipos usaban print statements y Datadog logs para debuggear sistemas de IA— hasta un conjunto de herramientas especializadas que capturan las dimensiones específicas de IA que las plataformas de observabilidad general no pueden: el contenido del prompt, la respuesta, los tokens consumidos, la jerarquía de llamadas en una cadena, y la evolución de la calidad a lo largo del tiempo. Elegir entre estas herramientas no es una decisión de cuál es "mejor" en abstracto sino de cuál encaja mejor con el stack tecnológico, el modelo de tenencia de datos, y las necesidades del equipo.

LangSmith —la plataforma de observabilidad nativa de LangChain— ofrece la integración más directa con el ecosistema de LangChain y LangGraph: activar `LANGCHAIN_TRACING_V2=true` y configurar `LANGCHAIN_API_KEY` captura automáticamente todas las cadenas y grafos de LangChain como trazas jerárquicas sin modificar ninguna línea de código de la aplicación. La interfaz de LangSmith incluye un árbol de trazas interactivo donde se puede navegar por cada span, ver el prompt exacto y la respuesta, y reproducir la llamada con diferentes parámetros desde el "Playground" integrado. La funcionalidad de Datasets & Testing permite crear un dataset a partir de trazas de producción con un click, ejecutar evaluaciones sobre él desde el pipeline de CI via el SDK, y mantener un historial de runs de evaluación con comparación de métricas. El modelo de pricing es por volumen de trazas y por usuario, con un tier gratuito limitado.

Langfuse es la alternativa open source y self-hosteable que provee funcionalidad comparable a LangSmith sin el modelo de pricing de tercero. Se puede desplegar con Docker Compose en minutos —PostgreSQL + Redis + el servidor de Langfuse— o como servicio managed en Langfuse Cloud. El SDK de Python expone una API de bajo nivel para instrumentación manual (`lf.trace()`, `trace.span()`, `span.generation()`) y tiene integraciones con LangChain, LlamaIndex, y cualquier código Python via decoradores. El prompt management de Langfuse permite editar, versionar y publicar prompts desde la interfaz web, accesibles desde el código con `langfuse.get_prompt("my-prompt", version=3)`, integrando el ciclo de iteración de prompts con el sistema de observabilidad.

OpenTelemetry es el estándar para equipos que ya tienen observabilidad OTel en su stack y quieren unificar el tracing de IA con el resto de la infraestructura. Las semantic conventions `gen_ai.*` del working group de OTel Gen AI estandarizan los atributos de los spans de IA, haciendo que las trazas de LLM sean comparables con las métricas de los otros servicios del sistema en el mismo backend de observabilidad. La ventaja es la portabilidad: el código de instrumentación es el mismo independientemente de si el backend es Jaeger, Zipkin, Datadog, Honeycomb o Grafana Tempo. La desventaja es que los backends de observabilidad general no tienen las interfaces especializadas de LangSmith o Langfuse para navegar trazas de IA, comparar prompts y gestionar datasets de evaluación.

## Herramientas de observabilidad para sistemas de IA

- **LangSmith:** configuración via variables de entorno; UI con árbol de trazas, playground interactivo y anotación humana de respuestas; Datasets & Testing para evaluación integrada; ideal para equipos que usan LangChain y LangGraph como framework principal.
- **Langfuse:** open source self-hosteable con Docker Compose o managed cloud; SDK para instrumentación manual y automática; prompt management con versionado accesible desde código; ideal para equipos con requisitos de soberanía de datos o con presupuesto limitado para herramientas SaaS.
- **OpenTelemetry + Grafana/Datadog:** instrumentación estándar con `opentelemetry-sdk`, semantic conventions `gen_ai.*`, exportadores a Prometheus, Grafana Tempo y backends existentes; ideal para equipos con stack de observabilidad OTel existente que quieren unificar la observabilidad de IA con el resto del sistema.
- **Weights & Biases Weave:** `@weave.op()` decorador que captura inputs y outputs de funciones Python que llaman a LLMs; integrado con el ecosistema de experimentos de W&B para comparar modelos fine-tuned vs base; ideal para equipos con workflows de MLOps que incluyen fine-tuning.
- **Arize AI Phoenix:** foco en detección de drift de datos y degradación de calidad; integración con LangChain y LlamaIndex; soporta evaluación de calidad con evals scores además de tracing; opción para equipos con requisitos de monitoreo de drift.

Elegir la herramienta de observabilidad antes de escribir la primera línea de código de producción y usarla desde el inicio es la práctica más impactante del capítulo: el costo de instrumentar retroactivamente un sistema en producción con código de terceros —especialmente LangChain— es desproporcionadamente mayor al costo de configurarla desde el primer día.

---

**Buena práctica:** Elegir la herramienta de observabilidad antes de escribir la primera línea de código de producción y usarla desde el inicio; el costo de instrumentar retroactivamente un sistema en producción —especialmente uno con código de framework como LangChain o LlamaIndex— es desproporcionado al costo de configurarla desde el día uno del proyecto.
