# Módulo 5 – Capítulo 01 – Sección 01

## Panorama general: herramientas, APIs, SDKs y frameworks para construir aplicaciones de IA

En el Módulo 4 aprendiste las arquitecturas de sistemas de IA —RAG, agentes, pipelines multi-agente, sistemas multi-modal— como patrones conceptuales que resuelven problemas de recuperación, razonamiento y acción. En este módulo aprenderás el ecosistema de herramientas con el que esas arquitecturas se implementan en producción: las APIs que proveen capacidad de inferencia, los SDKs que normalizan el acceso a esas APIs, los frameworks que reducen el código repetitivo en flujos complejos, y las herramientas de observabilidad que hacen comprensible el comportamiento de los sistemas en operación. La pregunta que guía este capítulo es: ¿qué herramienta resuelve qué problema, y cuándo añade más complejidad de la que elimina?

El ecosistema de desarrollo de IA en 2024 se articula en cuatro capas tecnológicas que se complementan sin solaparse. La capa más baja son los modelos fundacionales accesibles vía API REST: OpenAI con gpt-4o y la familia o1, Anthropic con Claude 3.5 Sonnet y Haiku, Google con Gemini 1.5 Pro y Flash vía Vertex AI o AI Studio. Estas APIs exponen el poder de inferencia de los modelos como servicios HTTP de pago por token, con autenticación por bearer token, límites de rate y contratos de SLA. Directamente sobre ellas se sitúan los SDKs oficiales —`openai` en Python y Node, `anthropic` en Python y TypeScript, `google-cloud-aiplatform`— que encapsulan la autenticación, la serialización JSON, el streaming de Server-Sent Events y la lógica de retry automático. Esta capa reduce una primera llamada al modelo a menos de diez líneas de código sin sacrificar control sobre ningún parámetro de la API.

La tercera capa son los frameworks de orquestación: LangChain, LlamaIndex y DSPy. Cada uno resuelve un problema diferente. LangChain organiza flujos de múltiples pasos con su protocolo de cadenas LCEL y ofrece una extensión para grafos de estado —LangGraph— que implementa agentes con memoria persistente, el mismo tipo de agente que el Módulo 4 describió arquitectónicamente. LlamaIndex está diseñado específicamente para el patrón RAG: su abstracción central es el índice sobre documentos, y su ecosistema de conectores de datos, query engines y pipelines de ingesta acelera la implementación de los sistemas de recuperación-síntesis del Módulo 4. DSPy representa un paradigma diferente: en lugar de escribir prompts manualmente, define el programa como una firma de entrada/salida y deja que el optimizador encuentre los prompts más efectivos mediante evaluación automática. Finalmente, la cuarta capa son las herramientas de observabilidad —LangSmith, Langfuse, OpenTelemetry— y de evaluación —RAGAS, DeepEval, TruLens— que instrumentan el comportamiento del sistema y miden su calidad de forma sistemática.

El mapeo entre arquitecturas del Módulo 4 y herramientas del Módulo 5 es directo: RAG se implementa con LlamaIndex más una base de datos vectorial (pgvector, Qdrant, Chroma); los agentes con estado se construyen con LangGraph más tool use; los pipelines multi-agente se orquestan con LangChain o implementación directa; la observabilidad de cualquier arquitectura se instrumenta con LangSmith o Langfuse.

## Componentes principales del ecosistema

- **APIs de modelos fundacionales:** endpoints HTTP REST que exponen inferencia bajo esquemas de autenticación basada en API keys, con límites de rate expresados en Tokens Per Minute (TPM) y Requests Per Minute (RPM) por tier de suscripción.
- **SDKs oficiales:** bibliotecas de cliente como `openai`, `anthropic` y `google-cloud-aiplatform` que gestionan retry automático, streaming SSE, tipado estricto de parámetros y lectura de credenciales desde variables de entorno.
- **Frameworks de orquestación:** LangChain para cadenas y agentes con estado, LlamaIndex para sistemas RAG con múltiples fuentes de datos, y DSPy para optimización declarativa de prompts mediante evaluación automática.
- **Herramientas de evaluación:** RAGAS, DeepEval y TruLens miden calidad de respuestas con métricas como faithfulness, answer relevancy y context recall de forma automatizada e integrable en pipelines de CI.
- **Herramientas de observabilidad:** LangSmith, Langfuse y OpenTelemetry con exportadores OTLP proveen trazas distribuidas, logs estructurados y métricas de latencia y costo por petición.

> **Nota del Arquitecto:** La tentación de adoptar prematuramente todo el stack disponible —LangChain, LlamaIndex, un vector store, una plataforma de observabilidad y un framework de evaluación desde el día uno— es la fuente más común de complejidad accidental en proyectos de IA. En la práctica, el stack evoluciona por necesidad demostrada: se añade LlamaIndex cuando el volumen de documentos supera los 10.000 chunks, se añade un framework de evaluación desde el primer sprint, y se adopta LangGraph cuando la lógica del agente requiere ciclos y estado persistente. Comenzar con el SDK puro del proveedor y un sistema de logging estructurado ya es un stack de producción viable para muchos casos de uso.

La maestría del AI Engineer no reside en dominar todas las herramientas del ecosistema sino en elegir con precisión qué capa usar para cada problema: las APIs para el acceso al modelo, los SDKs para el código de integración, los frameworks solo cuando la complejidad del flujo lo justifica, y la observabilidad siempre. Las secciones siguientes de este capítulo profundizan en cada una de estas capas: las diferencias entre las APIs de los tres proveedores principales, la instalación y configuración de los SDKs oficiales, la gestión segura de credenciales, y los criterios técnicos y económicos para elegir entre las herramientas disponibles según el caso de uso.

---

**Principio rector:** El ecosistema de IA es una pila de abstracciones donde cada capa tiene un costo en complejidad, dependencias y curva de aprendizaje; la maestría del AI Engineer reside en elegir el nivel mínimo necesario para resolver el problema sin introducir dependencias que el sistema no necesita todavía.
