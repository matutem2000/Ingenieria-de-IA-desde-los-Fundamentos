# Módulo 5 – Capítulo 07 – Sección 02

## Frameworks de evaluación: RAGAS, DeepEval y TruLens

La instrumentación manual de métricas de evaluación —calcular faithfulness, answer relevancy y context recall para cada caso de un dataset de 200 ejemplos, agregar los resultados, y comparar con el baseline— es un proceso que puede automatizarse completamente. Los frameworks de evaluación de IA hacen exactamente eso: proveen una API donde el dataset de evaluación se describe como una estructura de datos estándar, el cálculo de métricas se ejecuta con una llamada, y los resultados se presentan en formatos integrables con pipelines de CI. La elección entre los frameworks disponibles depende del tipo de sistema que se evalúa, de cómo el equipo prefiere consumir los resultados, y del modelo evaluador disponible para el presupuesto del proyecto.

RAGAS es el framework de referencia para la evaluación de sistemas RAG. Su API acepta un dataset de HuggingFace con columnas `question`, `answer`, `contexts` (lista de fragmentos recuperados), y opcionalmente `ground_truth` (la respuesta de referencia para métricas que la requieren). La función `evaluate(dataset, metrics=[faithfulness, answer_relevancy, context_recall])` devuelve un DataFrame con los scores por caso y las métricas agregadas. La integración directa con LangChain y LlamaIndex —`from ragas.integrations.langchain import EvaluatorChain`— captura automáticamente los contextos recuperados en cada query sin necesidad de instrumentar el código manualmente. El modelo evaluador interno —que RAGAS usa para calcular faithfulness y answer relevancy— puede configurarse con cualquier proveedor soportado por LangChain; usar un modelo más capaz que el evaluado mejora la confiabilidad pero aumenta el costo.

DeepEval ofrece un framework de evaluación más general, no específico de RAG, con una API compatible con pytest: los tests se escriben con `LLMTestCase`, se decoran con `@pytest.mark.deepeval`, y se ejecutan con `pytest`, produciendo output compatible con JUnit XML para integración directa en GitHub Actions sin infraestructura adicional. `AnswerRelevancyMetric(threshold=0.7)`, `FaithfulnessMetric(threshold=0.8)`, `HallucinationMetric(threshold=0.5)`, `ToxicityMetric(threshold=0.1)` son ejemplos de métricas configurables con umbrales de paso/fallo. La ventaja de DeepEval sobre RAGAS es su mayor variedad de métricas —incluyendo seguridad como toxicidad y bias— y su integración nativa con el flujo de testing de pytest; la desventaja es menor integración directa con LlamaIndex y LangChain.

TruLens añade una interfaz visual de dashboard web que permite explorar las trazas de evaluación, comparar experimentos y analizar distribuciones de scores a lo largo del tiempo, siendo especialmente útil para equipos que necesitan una interfaz visual en lugar de resultados en consola o CI. Los wrappers `TruChain` y `TruLlama` instrumentan LangChain y LlamaIndex respectivamente, capturando automáticamente la traza completa de cada query —recuperación, síntesis, herramientas— y calculando el "RAG triad" de TruLens: context relevance (¿el contexto es relevante para la pregunta?), groundedness (¿la respuesta está fundamentada en el contexto?) y answer relevance (¿la respuesta responde la pregunta?). `tru.get_leaderboard()` genera una tabla comparativa de experimentos con scores medios, facilitando la selección entre versiones de prompts o modelos.

## Componentes principales de los frameworks de evaluación

- **RAGAS `evaluate()`:** recibe un `Dataset` de HuggingFace con columnas `question`, `answer`, `contexts` y devuelve un dict con el score medio de cada métrica; análisis por caso disponible en el DataFrame resultante para identificar qué casos específicos fallan.
- **DeepEval `@pytest.mark.deepeval`:** decorador que ejecuta métricas sobre el `LLMTestCase` y genera reportes en `deepeval_results/`; el threshold de cada métrica es configurable por test; output JUnit XML para integración con CI sin configuración adicional.
- **TruLens `TruChain` y `TruLlama`:** wrappers que capturan automáticamente retrieval + generation como traza completa; `tru.get_leaderboard()` compara experimentos con visualización del RAG triad; accesible via dashboard web en `localhost:8501`.
- **Selección del modelo evaluador:** usar un modelo más capaz que el evaluado para el juez interno mejora la confiabilidad de las métricas; calcular el costo esperado del modelo evaluador antes de seleccionarlo (`dataset_size × avg_tokens_per_case × evaluador_precio`).
- **Costo de la evaluación automatizada:** para datasets de 100 a 500 casos el costo típico con modelos de evaluación eficientes es de $1 a $10 por run; calcularlo antes de configurar el scheduled job de CI para evitar sorpresas de facturación.

Un mapa unificado de herramientas de evaluación: RAGAS y DeepEval son las opciones principales para evaluación integrada en CI por su compatibilidad con pytest y JUnit XML; TruLens es la opción para equipos que priorizan exploración visual de trazas; LangSmith Datasets combina dataset management, evaluación y registro histórico en una sola plataforma. La elección no es excluyente: RAGAS para las métricas de RAG en CI y TruLens para la exploración exploratoria son combinaciones válidas.

---

**Principio rector:** La elección del framework de evaluación debe basarse en el tipo de sistema (RAG, agente, clasificador), el canal de consumo de resultados (CLI en CI, dashboard visual, integración pytest), y el modelo evaluador disponible en el presupuesto; más de un framework puede usarse para propósitos diferentes en el mismo sistema.
