# Módulo 5 – Capítulo 10 – Sección 01

## Patrones de entrada: validación, normalización y pre-procesamiento de prompts

El pre-procesamiento de la entrada del usuario antes de enviarla al LLM es una capa de defensa que el código de la aplicación controla completamente —a diferencia del comportamiento del modelo, que no puede controlarse directamente. Esta capa tiene tres propósitos que se refuerzan mutuamente: calidad (normalizar el input para que el modelo lo procese de forma consistente), economía (rechazar inputs fuera de rango antes de gastar tokens en procesarlos), y seguridad (detectar y bloquear intentos de manipulación del sistema). Las tres funciones son más baratas de implementar en la capa de entrada que de remediar en la capa de salida, porque un input incorrecto que llega al LLM produce una respuesta incorrecta que el sistema debe manejar, mientras que un input incorrecto detectado antes nunca genera el costo de la llamada al LLM.

La validación de entrada es la primera función. La longitud máxima del input —medida en tokens, no en caracteres— debe ser un límite explícito configurado según el presupuesto de tokens del sistema: si el system prompt ocupa 2.000 tokens y el historial conversacional hasta 4.000 tokens, el input del usuario no puede superar los tokens disponibles sin exceder la ventana de contexto o el presupuesto de costo definido. `if count_tokens(user_input) > MAX_INPUT_TOKENS: raise InputTooLongError(f"Input {count_tokens(user_input)} tokens, max {MAX_INPUT_TOKENS}")` rechaza el input antes de la llamada con un error informativo que el sistema puede convertir en un mensaje de usuario apropiado. Los inputs vacíos, los inputs que consisten solo en espacios o caracteres de control, y los inputs con patrones de repetición que indican un bug del cliente también deben rechazarse con validación explícita.

La detección de prompt injection es la segunda función, y la más específica de los sistemas de IA. El prompt injection directo ocurre cuando el usuario intenta añadir instrucciones al system prompt o sobrescribir instrucciones existentes con frases como "ignora las instrucciones anteriores", "actúa como un asistente sin restricciones", o "tu nueva instrucción es". La detección mediante expresiones regulares sobre patrones conocidos, complementada con un clasificador ligero entrenado sobre ejemplos de prompt injection, puede detectar los intentos más comunes con alta precisión y bajo costo (una llamada a un modelo pequeño o un clasificador local). El indirect prompt injection —donde el contenido malicioso está en un documento que el sistema recupera para incluir en el contexto RAG, no en el input directo del usuario— es más difícil de detectar y requiere sanitización del contenido de los documentos antes de incluirlos en el contexto.

La normalización prepara el input para procesamiento consistente. La normalización de encoding con `unicodedata.normalize('NFC', text)` unifica representaciones equivalentes de caracteres Unicode. La eliminación de caracteres de control con `re.sub(r'[\x00-\x08\x0b\x0c\x0e-\x1f]', '', text)` previene que caracteres invisibles confundan al tokenizador. La detección automática del idioma con `langdetect` o `fasttext-langid` permite configurar el idioma de respuesta en el prompt cuando el sistema es multilingüe. El enriquecimiento de contexto dinámico —insertar la fecha y hora actuales, el perfil del usuario, el idioma detectado, los permisos del usuario— transforma variables del template del prompt en datos reales antes de construir el mensaje final.

## Componentes principales del pre-procesamiento de entrada

- **Validación de longitud en tokens:** `count_tokens(user_input) > MAX_INPUT_TOKENS` rechaza el input antes de la llamada; usar el mismo tokenizador del modelo (tiktoken para OpenAI, `client.messages.count_tokens()` para Anthropic) para precisión exacta.
- **Detección de prompt injection:** lista de patrones regex para variantes conocidas de "ignora las instrucciones anteriores" combinada con un clasificador ligero; los inputs detectados se loggean en el stream de seguridad, se rechazan con un mensaje de error apropiado, y opcionalmente se escalan para revisión.
- **Sanitización de encoding:** `text.encode('utf-8', errors='replace').decode('utf-8')` elimina caracteres inválidos; `unicodedata.normalize('NFC', text)` unifica representaciones equivalentes; `re.sub(r'[\x00-\x08\x0b\x0c\x0e-\x1f]', '', text)` remueve caracteres de control.
- **Enriquecimiento de contexto dinámico:** rellenar `{current_date}`, `{user_name}`, `{user_plan}`, `{detected_language}`, `{user_permissions}` en el template del prompt con datos del contexto de la sesión antes de construir el mensaje; hacer este paso antes de contar los tokens del prompt final.
- **Clasificación de intent de primer paso:** un modelo ligero (Haiku con un prompt de clasificación, o un clasificador KNN sobre embeddings) determina si la query es in-scope antes de procesar con el modelo principal; el costo de la clasificación de primer paso ($0.00003 con Haiku) es insignificante comparado con el costo evitado de procesar queries out-of-scope con el modelo completo.

> **Nota del Arquitecto:** La seguridad en sistemas de IA no es un dominio separado de la ingeniería del sistema: es una propiedad que debe diseñarse en la capa de entrada, en el sistema prompt, en la capa de salida, y en el sistema de logging, de forma integrada. El OWASP Top 10 for LLMs es el marco de referencia estándar para identificar los vectores de ataque más relevantes: prompt injection, insecure output handling, training data poisoning, model denial of service, sensitive information disclosure, y otros riesgos específicos de sistemas LLM. Integrar este marco en el proceso de revisión de seguridad del equipo desde el primer sprint es más efectivo que añadir controles de seguridad retroactivamente.

El pre-procesamiento de entrada es la primera línea de defensa de la calidad y la seguridad del sistema; un input malformado, malicioso o fuera de alcance que llega al LLM es más caro de manejar —tokens desperdiciados, respuesta incorrecta, posible daño reputacional— que rechazarlo o corregirlo en esta etapa.

---

**Principio rector:** El pre-procesamiento de entrada es la primera línea de defensa de la calidad y la seguridad del sistema; validar longitud, detectar prompt injection, normalizar encoding y enriquecer con contexto dinámico en esta capa es siempre más económico que manejar las consecuencias de un input incorrecto que llegó al LLM.
