## DSPy: optimización declarativa de prompts

LangChain y LlamaIndex comparten un supuesto fundamental: el ingeniero escribe los prompts manualmente. El ingeniero decide las instrucciones del sistema, los ejemplos few-shot, el formato de salida solicitado y la cadena de razonamiento que el modelo debe seguir. DSPy —Declarative Self-improving Python— parte de un supuesto diferente: ¿por qué escribir prompts manualmente cuando es posible que un sistema los optimice automáticamente, dado un conjunto de ejemplos de entrenamiento y una función de evaluación? Esta pregunta define un paradigma nuevo que no es una variante de LangChain ni de LlamaIndex, sino una alternativa conceptualmente distinta para un problema específico: sistemas donde el prompt ideal no es obvio a priori y donde la evaluación automática puede guiar la búsqueda.

El modelo mental de DSPy tiene tres componentes. Las **Signatures** son la unidad de abstracción fundamental: definen la interfaz del módulo como un mapeo de campos de entrada a campos de salida con tipos y descripciones. `class QASignature(dspy.Signature): "Answer a question given context."; context: str = dspy.InputField(); question: str = dspy.InputField(); answer: str = dspy.OutputField()`. La Signature declara qué hace el módulo sin especificar cómo hacerlo: es la interfaz, no la implementación. Los **Módulos** son los componentes de construcción que implementan la Signature usando diferentes estrategias de prompting. `dspy.Predict(QASignature)` genera una respuesta directa; `dspy.ChainOfThought(QASignature)` instruye al modelo a razonar paso a paso antes de responder; `dspy.ReAct(QASignature, tools=[...])` implementa el patrón de agente con herramientas. La diferencia con LangChain es que ninguno de estos módulos tiene un prompt hardcodeado: el prompt es una variable que el sistema puede modificar.

Los **Teleprompters** (u Optimizadores) son el mecanismo que diferencia a DSPy de todos los demás frameworks. `dspy.teleprompt.BootstrapFewShot` toma el programa DSPy, un conjunto de ejemplos de entrenamiento, y una función de evaluación; ejecuta el programa sobre los ejemplos, evalúa los resultados, selecciona los mejores few-shot examples automáticamente, y los inyecta en los prompts de cada módulo. `dspy.teleprompt.MIPROv2` va más allá: optimiza simultáneamente las instrucciones del sistema y los few-shot examples usando un proceso de búsqueda en el espacio de prompts guiado por la métrica de evaluación. El resultado es un programa compilado donde cada módulo tiene los prompts optimizados para maximizar la métrica definida —faithfulness, accuracy, F1 o cualquier función custom— sobre el conjunto de validación.

El caso de uso donde DSPy tiene mayor ventaja sobre los enfoques manuales es cuando el prompt ideal es difícil de especificar por intuición: tareas de razonamiento complejo en dominios especializados, sistemas donde los few-shot examples mejoran significativamente el rendimiento pero elegirlos manualmente es costoso, y sistemas donde múltiples módulos encadenados necesitan ser co-optimizados porque el rendimiento de cada uno depende de los demás. La relación entre DSPy y el sistema de evaluación del capítulo 7 es directa: el dataset de evaluación curado es la materia prima del optimizador de DSPy; mientras mejor sea el dataset, más efectiva es la optimización.

DSPy tiene limitaciones conocidas que definen su alcance actual. El overhead de runtime del proceso de optimización puede ser significativo —del orden de decenas a centenares de llamadas al LLM para optimizar un programa simple—, por lo que la optimización se hace offline y el programa compilado se carga para inferencia. La reproducibilidad de la optimización no está garantizada porque el proceso depende de muestreo estocástico sobre el dataset. La compatibilidad con modelos open-source locales es funcional pero con mayor variabilidad en los resultados comparada con modelos de API como Claude o GPT-4.

## Componentes principales de DSPy

- **`dspy.Signature`:** contrato de entrada/salida del módulo; campos con `dspy.InputField()` y `dspy.OutputField()` más docstring descriptivo; no especifica el prompt, solo la interfaz.
- **`dspy.ChainOfThought`:** wrapper que añade razonamiento paso a paso antes del campo de salida; el proceso de razonamiento es un campo intermedio que el optimizador puede modificar para mejorar la calidad.
- **`dspy.teleprompt.BootstrapFewShot`:** optimizador que selecciona automáticamente few-shot examples del training set que maximizan la métrica de evaluación; requiere un conjunto de entrenamiento con pares (input, expected_output) y una función de evaluación.
- **`dspy.teleprompt.MIPROv2`:** optimizador de instrucciones y few-shot examples conjuntamente; utiliza un proceso de búsqueda en el espacio de prompts con evaluaciones múltiples; más poderoso que BootstrapFewShot pero con mayor costo computacional de optimización.
- **Compilación y serialización:** `compiled_program = optimizer.compile(program, trainset=trainset, metric=metric)` produce un programa con prompts optimizados; `compiled_program.save("program.json")` persiste los prompts para carga sin re-optimizar en cada inicio.

---

**Buena práctica:** DSPy es la elección correcta cuando el prompt ideal no es obvio por intuición y la evaluación automática puede guiar la búsqueda; el prerrequisito es tener un dataset de entrenamiento de calidad suficiente y una función de evaluación que correlacione con la calidad real del sistema —los mismos activos que el sistema de evaluación continua del capítulo 7 provee.
