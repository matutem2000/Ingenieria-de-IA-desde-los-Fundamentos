# Módulo 5 – Capítulo 03 – Sección 01

## Por qué usar un framework de orquestación: abstracción, cadenas y composición

Implementar un chatbot simple que toma el input del usuario, construye un prompt, llama al LLM y devuelve la respuesta requiere menos de 20 líneas de Python con el SDK puro del proveedor. Implementar un sistema que recupera documentos relevantes de múltiples fuentes, los incorpora al contexto, llama al LLM con historial conversacional, parsea la respuesta estructurada, invoca herramientas externas según el resultado, gestiona el estado de la conversación entre sesiones, y emite trazas de observabilidad en cada paso puede requerir centenares de líneas de código con gestión manual de estado, serialización, propagación de errores y manejo de casos borde que son difíciles de anticipar desde el inicio. Los frameworks de orquestación emergen como respuesta a esta complejidad creciente: ofrecen abstracciones que encapsulan los patrones recurrentes de los flujos de IA, reduciendo el código repetitivo y haciendo los flujos complejos legibles como composición de componentes.

La abstracción central que ofrecen estos frameworks es la idea de "cadena" o "pipeline": una secuencia de pasos donde la salida de cada componente es la entrada del siguiente, con manejo automático de tipos, serialización, propagación de errores y observabilidad integrada. LangChain Expression Language (LCEL) modela esta composición con el operador `|`: `chain = prompt_template | llm | output_parser` crea un objeto Runnable ejecutable donde el sistema gestiona internamente el formateo del prompt, la llamada al LLM, el parseo de la respuesta, y potencialmente el retry si el parseo falla. Esta abstracción declarativa hace que el código exprese la intención del flujo —qué pasos componen el pipeline— sin mezclarlo con los detalles de implementación de cada paso.

La intercambiabilidad de componentes es otro beneficio concreto. Una cadena LCEL que usa `ChatOpenAI` puede cambiar al modelo de Anthropic reemplazando el componente LLM por `ChatAnthropic` sin modificar el prompt template ni el parser. En producción, esta propiedad permite hacer A/B testing de proveedores, fallback entre proveedores en caso de degradación, y migración de modelo sin reescribir el pipeline. El mismo principio aplica a los otros componentes: el vector store puede cambiar de Chroma a pgvector, el parser de `StrOutputParser` a `PydanticOutputParser`, sin que el resto del pipeline necesite modificarse.

La observabilidad integrada es quizás el argumento más práctico para adoptar un framework en proyectos serios. LangChain emite callbacks en cada paso de la cadena que herramientas como LangSmith o Langfuse capturan automáticamente: cada llamada al LLM, cada consulta al vector store, cada invocación de herramienta queda registrada con su timing, los tokens consumidos y los datos de entrada y salida. Instrumentar este nivel de observabilidad manualmente —sin framework— requiere añadir código de logging en cada función, propagar context IDs, y gestionar la jerarquía de spans: trabajo significativo que el framework hace gratis cuando se tiene la integración configurada.

## Conceptos clave de la orquestación

- **Cadena (chain):** secuencia de componentes que transforma una entrada en una salida mediante llamadas a LLMs, herramientas y transformaciones de datos; es la unidad de composición fundamental y puede anidarse dentro de cadenas más complejas.
- **Runnable interface (LCEL):** protocolo común que todos los componentes de LangChain implementan con métodos `invoke()`, `stream()`, `batch()` y sus variantes async, haciendo que sean conectables con `|` independientemente de su tipo interno.
- **Memory y state management:** abstracciones para mantener historial conversacional en memoria, Redis, bases de datos SQL o vectoriales, con compresión automática del historial cuando el contexto se aproxima al límite del modelo.
- **Composición declarativa vs imperativa:** declarar el flujo como composición de componentes facilita la inspección con herramientas de debugging, el testing por partes con mocks de componentes individuales, y la modificación sin tocar la lógica de integración de los demás pasos.
- **Observabilidad integrada:** LangChain emite eventos en cada paso que herramientas como LangSmith capturan sin modificar el código, proveyendo trazas jerarquizadas de cada request con latencia, tokens y datos de cada componente.

Un framework de orquestación justifica su adopción cuando el beneficio en legibilidad, mantenibilidad y reutilización de componentes supera el costo de aprender su modelo mental y gestionar sus actualizaciones frecuentes de API. Las secciones siguientes examinan los tres frameworks principales —LangChain, LlamaIndex y DSPy— con sus fortalezas específicas, los casos de uso donde cada uno brilla, y los criterios objetivos para elegir entre ellos.
