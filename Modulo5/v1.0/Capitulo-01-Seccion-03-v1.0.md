# Módulo 5 – Capítulo 01 – Sección 03

## SDKs oficiales: instalación, configuración y primeras llamadas

La diferencia entre llamar a una API de LLM con `urllib.request` o `httpx` manualmente y usar el SDK oficial del proveedor no es solo de comodidad sintáctica: los SDKs encapsulan decisiones de ingeniería que tardarían días en implementarse correctamente desde cero. El retry automático con backoff exponencial ante errores transitorios, el streaming de Server-Sent Events con buffering correcto, el tipado estricto que detecta parámetros inválidos antes de hacer la llamada, la rotación automática de bases de URL para diferentes regiones, y la gestión del ciclo de vida de las conexiones HTTP con pooling —todo esto viene incluido y probado. La pregunta no es si usar el SDK sino cuál, cuándo actualizarlo y qué aspectos de su configuración merecen atención al momento de la instalación.

El SDK de OpenAI se instala con `pip install openai` y su instancia principal es `client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])`. Si la variable de entorno `OPENAI_API_KEY` existe en el entorno del proceso, el SDK la lee automáticamente sin que el argumento `api_key` sea necesario. La llamada síncrona básica es `response = client.chat.completions.create(model="gpt-4o-2024-08-06", messages=[{"role": "user", "content": "Hola"}], max_tokens=256)` y la respuesta se accede como `response.choices[0].message.content`. La variante asíncrona usa `AsyncOpenAI` y es directamente compatible con frameworks como FastAPI. El SDK también expone el atributo `response.usage` con `prompt_tokens`, `completion_tokens` y `total_tokens`, indispensable para el seguimiento de costos.

El SDK de Anthropic (`pip install anthropic`) sigue una arquitectura similar: `client = anthropic.Anthropic()` lee `ANTHROPIC_API_KEY` del entorno, y `client.messages.create(model="claude-3-5-sonnet-20241022", max_tokens=256, system="Eres un asistente técnico.", messages=[{"role": "user", "content": "Hola"}])` realiza la llamada. Una diferencia notable en el tipado es que el SDK de Anthropic genera sus tipos desde el schema OpenAPI de la API, lo que significa que los atributos de la respuesta son objetos fuertemente tipados —`response.content[0].text`, `response.usage.input_tokens`— en lugar de dicts. El SDK también expone `client.messages.count_tokens()` para contar tokens de un mensaje antes de enviarlo, útil para decisiones de costo previas a la llamada.

Google ofrece dos SDKs según la ruta de acceso. Para AI Studio: `pip install google-generativeai` y `genai.configure(api_key=os.environ["GOOGLE_API_KEY"])`; la llamada es `model = genai.GenerativeModel("gemini-1.5-pro"); response = model.generate_content("Hola")`. Para Vertex AI: `pip install google-cloud-aiplatform` con autenticación por Application Default Credentials (`gcloud auth application-default login` en local, service account en CI/CD); la llamada requiere configurar primero el proyecto y la región con `vertexai.init(project=PROJECT_ID, location="us-central1")` antes de cualquier llamada al modelo.

## Componentes principales de los SDKs

- **Gestión de autenticación:** los SDKs leen la API key desde variable de entorno por convención (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) sin requerir configuración explícita, evitando el hardcoding de credenciales en el código fuente.
- **Tipado estricto con autocompletado:** los SDKs modernos usan tipos generados desde especificaciones OpenAPI, proporcionando autocompletado en IDEs y detectando parámetros inválidos antes de la llamada, reduciendo el tiempo de depuración.
- **Retry automático con backoff:** el SDK de OpenAI reintenta hasta 2 veces por defecto con jitter ante errores transitorios; el SDK de Anthropic tiene `max_retries` configurables (default 2) para errores 429 y 529.
- **Streaming nativo:** `stream=True` en OpenAI y el context manager `with client.messages.stream(...) as stream` en Anthropic devuelven iteradores de eventos delta, con acumulación automática de la respuesta completa disponible via `stream.get_final_message()`.
- **Configuración de timeout y base_url:** ambos SDKs permiten configurar `timeout` (default 600s en OpenAI) y `base_url` para redirigir a proxies, gateways internos o servicios compatibles como Azure OpenAI Service con su propio `api_version`.

> **Nota del Arquitecto:** El parámetro `base_url` de los SDKs de OpenAI y Anthropic es más valioso de lo que parece inicialmente. En sistemas con múltiples proveedores, configurar `base_url` para apuntar a un proxy interno como LiteLLM permite redirigir todas las llamadas a través de un gateway centralizado sin cambiar ninguna línea de código de aplicación: el gateway centraliza el logging, el rate limiting interno y el failover entre proveedores. Configurar el gateway desde el inicio del proyecto, incluso si al principio solo hay un proveedor, es una decisión de diseño de bajo costo con alto retorno operacional.

El patrón de uso recomendado para proyectos de producción es instanciar el cliente una sola vez al arrancar la aplicación y reutilizarlo en todas las llamadas, en lugar de instanciarlo por request. El cliente mantiene internamente un pool de conexiones HTTP que se reutilizan entre llamadas, reduciendo la latencia de establecimiento de conexión. En aplicaciones web con FastAPI o Flask, el cliente se instancia como dependencia de la aplicación y se inyecta vía `Depends()` o como variable de módulo. La siguiente sección aborda el aspecto de seguridad más importante de trabajar con SDKs: la gestión de las credenciales que esos clientes necesitan para autenticarse.

---

**Principio rector:** Usar el SDK oficial en lugar de llamadas HTTP directas no solo reduce el código necesario; garantiza compatibilidad automática con actualizaciones de protocolo del proveedor, retry correcto ante errores transitorios, y tipado estricto que previene errores silenciosos en producción.
