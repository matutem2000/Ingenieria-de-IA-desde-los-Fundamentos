# Consulta expandida: HyDE, multi-query y descomposición de preguntas complejas

Las técnicas de consulta expandida abordan una limitación fundamental de la búsqueda vectorial: el vector de la query del usuario raramente describe con la misma terminología y estructura que el texto del documento donde está la respuesta, produciendo un "vocabulary mismatch" que reduce el score de similitud coseno incluso cuando la información existe en el índice. HyDE (Hypothetical Document Embeddings), propuesto por Gao et al. en 2022, resuelve esto de forma contraintuitiva: en lugar de embedir la query directamente, pide al LLM que genere un documento hipotético que respondería la query, luego embide ese documento hipotético para la búsqueda vectorial; la intuición es que el documento hipotético usa el vocabulario y la estructura del corpus de documentos reales, produciendo un vector más cercano en el espacio latente al documento real con la respuesta. Multi-query generation, implementado en LangChain como `MultiQueryRetriever`, reformula la query original en 3–5 variantes usando un LLM y ejecuta búsquedas separadas para cada variante; los resultados se combinan con deduplicación, aumentando el Recall@K porque distintas reformulaciones capturan aspectos diferentes de la query original. La descomposición de preguntas complejas (query decomposition) divide queries compuestas ("¿Cuáles son las diferencias y similitudes entre RAG y fine-tuning para casos de uso legales?") en sub-queries atómicas que se recuperan y responden independientemente antes de sintetizar la respuesta final.

## Técnicas de expansión de consulta

- HyDE (Hypothetical Document Embeddings): generar con LLM un documento de 100–200 palabras que respondería la query → embedir el documento hipotético → usar su vector para búsqueda vectorial; mejora Recall@5 en 5–15% para queries cortas y abstractas; no funciona bien para queries factuales muy específicas donde el LLM alucina datos incorrectos en el documento hipotético
- Multi-query retrieval: generar 3–5 reformulaciones de la query con diferentes ángulos (formal, coloquial, técnico, por sinónimos) → ejecutar búsqueda para cada reformulación → deduplicar resultados por ID de chunk → retornar la unión de todos los resultados únicos; aumenta Recall@K a costa de K veces más llamadas al retriever
- Step-back prompting: pedir al LLM que identifique el concepto o principio general detrás de la query específica ("¿Qué temperatura necesita el agua para hervir a 3000m de altitud?" → "¿Cómo afecta la presión atmosférica al punto de ebullición?") y buscar el concepto general además de la query original
- Query decomposition: descomponer queries compuestas en sub-preguntas atómicas usando un LLM, responder cada sub-pregunta con RAG de forma independiente y sintetizar las respuestas parciales en una respuesta final; adecuado para queries de comparación, contraste o síntesis multi-documento
- Corrective query expansion: analizar los chunks recuperados en la primera búsqueda, identificar términos técnicos relevantes que no estaban en la query original, reformular la query incorporando esos términos y ejecutar una segunda búsqueda; implementable con un LLM pequeño como clasificador de relevancia de términos
- Costo-beneficio de la expansión: cada técnica de expansión añade latencia (HyDE: +500ms por inferencia LLM; multi-query: +2–5 llamadas al retriever) y costo (tokens LLM adicionales); evaluar el delta de Recall@K sobre el dataset de evaluación para determinar si el overhead es justificado en el caso de uso específico

## Para recordar

La expansión de consultas es especialmente valiosa cuando el corpus usa terminología técnica o formal diferente a las queries de los usuarios finales; en ese escenario, HyDE o multi-query pueden recuperar documentos que la búsqueda directa sistematicamente pierde.
