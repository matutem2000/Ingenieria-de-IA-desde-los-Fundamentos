# Módulo 6 – Capítulo 08 – Sección 01

## RAG multimodal: imágenes, audio y documentos con tablas y diagramas

El conocimiento de una organización raramente existe exclusivamente en forma de texto plano. Un manual técnico de mantenimiento de aeronaves tiene diagramas de los sistemas hidráulicos, tablas de tolerancias de componentes y fotografías de los procedimientos. Un reporte financiero trimestral tiene gráficos de tendencias, tablas de resultados por segmento y notas al pie con contexto regulatorio. Una sesión de entrenamiento en vídeo tiene la voz del instructor, capturas de pantalla de la interfaz y subtítulos de texto. Si el sistema RAG solo indexa el texto plano extraíble de estos documentos, está accediendo a una fracción del conocimiento real que contienen; en muchos corpus empresariales, entre el 30% y el 60% del conocimiento relevante está codificado en formatos no textuales que un pipeline RAG estándar ignora. RAG multimodal extiende el paradigma para incluir estos formatos como fuentes de conocimiento recuperables.

La arquitectura general del RAG multimodal tiene dos enfoques principales con distintos trade-offs de complejidad, calidad y costo. El **enfoque caption-based** convierte cada elemento no textual en texto mediante modelos de visión o herramientas de extracción especializadas, y luego indexa ese texto con embeddings estándar. Una tabla de un contrato se convierte en Markdown con separadores `|`; un diagrama de flujo se convierte en una descripción textual de sus nodos y relaciones generada por GPT-4V o Claude Sonnet; un gráfico de barras se convierte en "un gráfico de barras que muestra las ventas trimestrales del Q1 al Q4 de 2024, con Q3 como pico de $2.3M y Q1 como mínimo de $1.1M". Este texto convertido se indexa como cualquier otro chunk de texto, con la ventaja de que puede recuperarse con el mismo pipeline de búsqueda semántica existente sin cambios en la infraestructura. La desventaja es que la calidad de la recuperación depende de la calidad de la conversión: una caption imprecisa produce un vector incorrecto que no será recuperado para las queries relevantes.

El **enfoque native multimodal embedding** usa modelos de embedding que pueden generar vectores en el mismo espacio latente para texto e imágenes, permitiendo búsqueda cross-modal: una query en texto puede recuperar directamente imágenes relevantes sin necesidad de que las imágenes tengan captions textuales. CLIP (Contrastive Language-Image Pre-Training, OpenAI), SigLIP (Sigmoid Loss for Language Image Pre-Training, Google) y voyage-multimodal-3 (Voyage AI) son los modelos más representativos de este enfoque. Un vector generado por CLIP para la query "diagrama de instalación del motor" puede recuperar directamente imágenes de diagramas de instalación del corpus aunque no tengan ninguna descripción textual asociada. Este enfoque es conceptualmente más elegante pero requiere infraestructura de embedding más compleja y modelos que soporten ambas modalidades.

Las **herramientas de extracción de contenido no textual** son el componente que más frecuentemente determina la calidad del RAG multimodal. **Docling** de IBM es actualmente la herramienta open source más robusta para documentos complejos: usa modelos de comprensión de layout visual para detectar columnas, tablas, figuras y su jerarquía, reconstruye el orden de lectura correcto incluso en layouts complejos de múltiples columnas, y extrae tablas en formato estructurado con alta fidelidad (>90% de accuracy para tablas con bordes explícitos). **Azure Document Intelligence** (anteriormente Form Recognizer) ofrece capacidades similares como servicio managed con soporte para formularios preentrenados de tipos de documentos comunes (facturas, recibos, contratos). **Camelot** y **pdfplumber** son opciones ligeras para extracción de tablas de PDFs con bordes explícitos, con precisión más baja para layouts complejos pero sin la dependencia de un servicio externo.

El **procesamiento de audio** sigue el patrón caption-based de forma natural: **Whisper** de OpenAI (disponible en varios tamaños desde tiny hasta large-v3) transcribe audio a texto con accuracy superior al 95% para inglés y soporte de 99 idiomas, con timestamps por segmento que permiten recuperar el segmento específico del audio que contiene la información relevante. Las transcripciones se indexan como texto estándar, con un metadato de timestamp que el sistema puede usar para generar un enlace al segmento exacto del vídeo o audio como fuente citada en la respuesta del LLM.

## Técnicas y herramientas para RAG multimodal

- **Extracción de tablas de PDFs**: Docling (IBM, open source) para layouts complejos; Camelot lattice para tablas con bordes (>95% accuracy); Camelot stream para tablas sin bordes (70–85%); Azure Document Intelligence para formularios y tablas en documentos escaneados; representar en Markdown con | separadores para indexación textual.
- **Caption generation para imágenes**: GPT-4o o Claude Sonnet para generación de captions descriptivas de 100–200 palabras; incluir en el caption: tipo de imagen, elementos principales, datos numéricos visibles, pregunta implícita que responde la imagen; la calidad del caption determina directamente el recall de recuperación de la imagen.
- **CLIP/SigLIP para búsqueda cross-modal**: vectores en el mismo espacio latente para texto e imágenes; búsqueda semántica directa de imágenes desde queries de texto; ideal para corpus con imágenes que no tienen captions naturales; requiere base vectorial que soporte almacenamiento de embeddings de imagen.
- **Whisper para transcripción de audio**: modelos desde tiny (39M params) hasta large-v3 (1550M params); accuracy >95% en inglés, >85% en la mayoría de idiomas europeos; timestamps por segmento para recuperación precisa; disponible como API (openai.audio.transcriptions) o self-hosted.
- **Layout analysis para documentos complejos**: Docling y Azure Document Intelligence detectan estructura espacial (columnas, encabezados, footers) y reconstruyen el orden de lectura lógico; crítico para PDFs de reportes financieros, artículos científicos y contratos con layouts no lineales.
- **Multimodal context para el LLM generador**: enviar imágenes recuperadas como base64 a modelos con visión (GPT-4o, Claude Sonnet); enviar tablas como Markdown a modelos de solo texto; los modelos con visión pueden razonar directamente sobre tablas e imágenes en el contexto sin conversión previa.

El RAG multimodal amplía dramáticamente el alcance del sistema, pero añade complejidad significativa en la etapa de ingesta. La regla práctica es empezar por los formatos más frecuentes en el corpus específico: en la mayoría de los corpus empresariales, las tablas de PDFs y las imágenes captionadas cubren el 80% del conocimiento no textual con el 20% del esfuerzo de implementación.
