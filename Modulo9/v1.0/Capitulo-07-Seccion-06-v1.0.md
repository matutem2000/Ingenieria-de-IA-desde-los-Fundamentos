# Módulo 9 – Capítulo 07 – Sección 06

## Cierre: el hardening del endpoint es la primera línea de defensa del sistema de IA

Las cinco capas del hardening del endpoint —autenticación y autorización, rate limiting, input validation, output filtering, y WAF— no son controles independientes que se eligen según el presupuesto o la conveniencia; son las capas de un filtro que cada request debe atravesar en el orden específico que refleja el ciclo de vida de la request. La autenticación y autorización primero porque sin ellas el resto carece de contexto. El rate limiting segundo porque limita el volumen antes de que los controles más costosos (clasificadores semánticos) deban procesar un ataque de alta frecuencia. El input validation tercero porque filtra el contenido antes de que llegue al modelo. El output validation cuarto porque es la red de seguridad después del modelo. El WAF como capa perimetral que opera en paralelo con el ciclo de vida interno. Reordenar estas capas o eliminar alguna no equivale a elegir un nivel de seguridad diferente; equivale a dejar brechas estructurales que los atacantes explotan sistemáticamente.

El hardening del endpoint es la primera línea de defensa del sistema, pero tiene una limitación que los equipos maduros reconocen explícitamente: no previene todos los ataques. Los ataques de data poisoning que ocurren en el pipeline de entrenamiento operan por debajo del endpoint. Los ataques de model extraction distribuidos que se mantienen por debajo de los umbrales de rate limiting pueden ser invisibles durante semanas. Los ataques adversariales en texto contra los clasificadores-guardrail pueden eludir el input filter. La primera línea de defensa robusta eleva significativamente el costo de cualquier ataque exitoso, pero no reemplaza las capas de defensa siguientes —sandboxing, autorización granular de herramientas, logging e inmutabilidad de auditoría— que son necesarias para contener el daño cuando la primera línea es superada.

En términos prácticos, la mayoría de los intentos de abuso de sistemas de IA en producción son oportunistas, no sofisticados: bots que intentan usar la API sin autenticación, usuarios que prueban jailbreaks conocidos que circulan en comunidades online, competidores que intentan consultas sistemáticas de baja frecuencia para replicar el comportamiento del sistema. Un hardening correcto de la primera línea —autenticación, rate limiting calibrado, LlamaGuard en input y output— es suficiente para neutralizar la gran mayoría de estos intentos. Los ataques sofisticados de actores con alta motivación y capacidades avanzadas requieren defensa en profundidad que va más allá del endpoint, pero esa defensa en profundidad no es efectiva sin una primera línea robusta.

## Conceptos clave del capítulo

- **Autenticación y autorización granular:** OAuth 2.0 / API keys con jerarquía de tres niveles, RBAC por modelo y capacidad, JWT con claims específicos de IA, secrets en HashiCorp Vault nunca en código ni contexto del modelo.
- **Rate limiting multidimensional:** RPM + TPM + ventanas largas para detección de extracción distribuida; límites independientes por categoría de endpoint; Sliding Window Counter en Redis para producción; detección de model extraction mediante análisis de distribución de topics.
- **Input validation semántica:** límites de longitud en tokens con el tokenizador específico del modelo, LlamaGuard-3 para clasificación semántica, Prompt Guard para detección específica de injection, validación de schema para inputs estructurados.
- **Output filtering:** LlamaGuard sobre el output como segunda línea de defensa, Presidio para redacción de PII, detección del system prompt en la respuesta, enforcement de policies específicas de la aplicación, consideraciones de streaming.
- **WAF dual-layer:** capa HTTP (AWS WAF, Cloudflare, ModSecurity) para ataques perimetrales convencionales + capa semántica (Lakera Guard, Prompt Security, Rebuff) para ataques específicos de LLMs; alternativas on-premises disponibles para entornos self-hosted.

*"Defense is difficult not because attackers are smart, but because defenders must be right every time while attackers only need to be right once."* — John Chambers, ex CEO de Cisco, sobre el principio de asimetría fundamental entre atacantes y defensores que hace al hardening de la primera línea crítico: cuanto más costoso sea el único intento exitoso del atacante, más efectiva es la primera línea de defensa.
