# Módulo 9 – Capítulo 06 – Sección 01

## PII en sistemas de IA: detección, anonimización y pseudonimización

La gestión de Información de Identificación Personal (PII) en sistemas de IA es técnicamente más compleja que en sistemas tradicionales de procesamiento de datos porque el PII puede aparecer en múltiples capas del sistema, en formatos inesperados, y puede ser introducido por componentes que en sistemas clásicos no procesarían datos personales. Un sistema RAG que indexa documentos corporativos puede indexar inadvertidamente documentos con nombres de clientes, números de identificación o datos de salud. Un historial de conversación almacenado para dar continuidad a sesiones multi-turn acumula cualquier dato personal que el usuario mencione. Los logs de inferencia registran el input completo del usuario, que puede incluir PII significativa. Y el modelo mismo —si fue fine-tuneado con datos que contenían PII— puede reproducir verbatim datos personales que "memorizó" del corpus de entrenamiento. Ninguno de estos vectores existe de manera equivalente en sistemas CRUD convencionales.

La detección automatizada de PII en texto es el prerrequisito para cualquier control de privacidad efectivo. Microsoft Presidio es la herramienta open-source de referencia: soporta más de 50 entidades PII en múltiples idiomas, incluyendo nombres, emails, números de teléfono, documentos de identidad (SSN, pasaportes, NIE), números de tarjeta de crédito, coordenadas geográficas, y credenciales de acceso. Presidio usa una combinación de reconocimiento de entidades nombradas (NER) con modelos de spaCy, expresiones regulares para formatos estructurados (emails, números de tarjeta), y listas de contexto para mejorar la precisión. Amazon Comprehend PII Detection ofrece una alternativa gestionada con integración directa con otros servicios AWS. Para PII contextual —"mi jefe Juan López trabaja en el departamento de finanzas"— los modelos NER genéricos tienen mayor tasa de falsos negativos y pueden requerir fine-tuning específico del dominio.

La anonimización y la pseudonimización son técnicas complementarias con diferentes trade-offs para sistemas de IA. La anonimización elimina el PII de manera irreversible —reemplazando "Juan López" con "[REDACTED]" o con una cadena hash— y es la opción más segura para contextos donde el PII no es necesario para la tarea. Su limitación es que puede degradar la calidad del modelo si el PII era semánticamente relevante: un sistema de análisis de contratos que recibe los contratos con todos los nombres redactados pierde señales de relaciones entre personas que podrían ser relevantes para el análisis. La pseudonimización reemplaza el PII con identificadores consistentes y reversibles —"Juan López" → "PERSON_1", y esta sustitución se aplica consistentemente en todo el documento— preservando las relaciones semánticas mientras oculta la identidad real. La tabla de mapeo entre PII real e identificadores pseudonimizados debe almacenarse con cifrado y controles de acceso estrictos, y es el activo de privacidad más crítico del sistema.

## Aspectos técnicos

- **Microsoft Presidio (open-source):** 50+ entidades PII en múltiples idiomas, combinando NER (spaCy), regex para formatos estructurados, y listas de contexto; configurable con entidades personalizadas para PII específica del dominio; disponible como servicio REST o como librería Python.
- **Anonimización en el pipeline RAG:** documentos deben pasar por detección y redacción de PII con Presidio antes de ser indexados en el vectorstore; el mismo documento sin PII sirve a todos los usuarios, preservando la utilidad del sistema sin exponer datos personales entre usuarios.
- **Pseudonimización para fine-tuning:** sustitución consistente de PII por placeholders (PERSON_1, ORG_2, LOCATION_3) preserva relaciones semánticas mientras protege la identidad; la tabla de mapeo debe almacenarse con cifrado AES-256 y acceso auditado.
- **PII en el historial de conversación:** los sistemas con memoria multi-turn acumulan PII del usuario; implementar TTL (tiempo de vida) para el historial, cifrado por usuario, y mecanismos de borrado a petición del usuario para cumplir con el derecho al olvido del GDPR.
- **Detección de PII en outputs:** escanear respuestas del modelo con Presidio antes de entregarlas al cliente para detectar PII no intencional proveniente de memorización del pretraining o de PII del contexto del usuario incluida en la respuesta sin necesidad.

> **Nota del Arquitecto:** La implementación de Presidio en el pipeline RAG tiene una trampa frecuente: anonimizar los documentos antes de indexarlos pero olvidar anonimizar los metadatos del chunk —autor del documento, fecha de creación, departamento propietario— que se incluyen en la respuesta del LLM junto con el contenido del chunk. He visto sistemas donde el contenido del documento estaba correctamente redactado pero el metadata incluía el nombre completo del empleado que creó el documento, la fecha exacta de una transacción, o el número de empleado del departamento. Los metadatos deben pasar por el mismo pipeline de detección y redacción que el contenido.

La gestión de PII en sistemas de IA debe cubrir todas las capas donde puede aparecer — input del usuario, corpus RAG, historial de conversación, logs de inferencia, outputs del modelo — con controles técnicos específicos en cada capa, porque la detección en una sola capa deja las demás completamente desprotegidas.
