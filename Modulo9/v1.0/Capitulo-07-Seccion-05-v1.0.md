# Módulo 9 – Capítulo 07 – Sección 05

## Web Application Firewall adaptado para APIs de IA

Los Web Application Firewalls tradicionales —AWS WAF, Cloudflare WAF, ModSecurity— protegen aplicaciones web contra ataques cuya firma está en la estructura de la request HTTP: SQL injection en parámetros de URL, XSS en campos de formulario, path traversal en rutas, CSRF en cookies. Para APIs de IA, esta protección de capa HTTP es necesaria pero radicalmente insuficiente: un prompt injection no tiene firma a nivel de protocolo HTTP porque el payload malicioso es texto semánticamente válido en el campo `message.content` del JSON. El WAF tradicional ve una request POST a `/v1/chat/completions` con JSON bien formado y la pasa sin alarma, sin capacidad de detectar que el texto de ese JSON es un jailbreak o una prompt injection sofisticada.

Un WAF para APIs de IA debe operar en dos capas independientes que se complementan. La capa HTTP clásica —AWS WAF, Cloudflare WAF— proporciona protección perimetral convencional: rate limiting de primera línea por IP, bloqueo de rangos de IPs maliciosas según listas de threat intel, protección contra bots, y defensa ante ataques de capa HTTP convencionales que también pueden intentarse contra endpoints de IA. Esta capa no puede eliminarse porque los atacantes no solo usan técnicas específicas de IA; también prueban técnicas convencionales contra cualquier endpoint expuesto. La capa semántica especializada para IA complementa la capa HTTP con capacidades que esta no puede proporcionar: análisis del contenido del prompt para detectar injection, tracking de patrones de uso a lo largo de múltiples sessions para detectar extracción sistemática, y análisis de riesgo basado en la semántica del input.

En el ecosistema de WAF semántico para IA destacan tres soluciones con diferentes trade-offs. Lakera Guard es un proxy inverso para APIs de LLMs que intercepta requests y responses, aplica clasificadores de prompt injection y jailbreak entrenados en un dataset propietario, y proporciona scores de riesgo por request; su arquitectura de sidecar no requiere modificar el código de la aplicación, lo que facilita la adopción. Prompt Security tiene un enfoque similar pero añade análisis de comportamiento entre sessions y shadow mode —logging de todos los prompts sin bloqueo para análisis forense antes de activar el modo de bloqueo en producción. Rebuff es la alternativa open-source: una librería Python que combina tres capas de detección (heurísticas de reglas rápidas, LLM-based detection con un modelo secundario que evalúa si el input contiene injection, y VectorDB-based detection que compara el embedding del input contra una base de ejemplos conocidos de injection), integrable directamente en la aplicación sin proxy externo.

Los equipos que operan en entornos self-hosted o on-premises —sin acceso a servicios cloud específicos como AWS WAF o Cloudflare— deben considerar ModSecurity con el ruleset de OWASP Core Rule Set para la capa HTTP, y Rebuff o una implementación personalizada de LlamaGuard como capa semántica. OPA (Open Policy Agent) puede complementar el WAF con políticas de autorización granular basadas en el contenido de la request, implementando reglas como "usuarios del role basic no pueden enviar requests con contextos de más de X tokens" o "este endpoint solo es accesible desde rangos de IP de la red corporativa".

## Aspectos técnicos

- **WAF tradicional para la capa HTTP:** AWS WAF, Cloudflare WAF, o ModSecurity con OWASP Core Rule Set para ataques convencionales (rate limiting por IP, bots, ataques de capa HTTP); necesario pero insuficiente para detectar ataques específicos de LLMs.
- **Lakera Guard:** proxy inverso de sidecar para APIs de LLMs; clasificadores de prompt injection y jailbreak con dataset propietario; scores de riesgo por request; soporta OpenAI, Anthropic y endpoints de modelos propios; no requiere modificar código de aplicación.
- **Prompt Security:** similar a Lakera con análisis de comportamiento entre sessions; shadow mode para logging sin bloqueo durante la fase de calibración antes de activar el modo restrictivo en producción.
- **Rebuff (open-source):** tres capas de detección combinadas (heurísticas, LLM-as-detector, VectorDB similarity search); integrable como librería Python directamente en la aplicación; adecuado para entornos self-hosted donde los proxies externos no son viables.
- **Alternativas on-premises:** ModSecurity (OWASP CRS) para la capa HTTP + Rebuff o LlamaGuard embebido para la capa semántica + OPA para políticas de autorización granular basadas en el contenido de la request.

Un WAF para APIs de IA debe operar en las dos capas independientemente y en paralelo: la capa HTTP clásica para protección perimetral convencional, y la capa semántica especializada para detectar ataques específicos de LLMs que no tienen firma a nivel de protocolo HTTP.
