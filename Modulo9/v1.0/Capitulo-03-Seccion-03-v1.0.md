## Model extraction: reconstruir el comportamiento de un modelo propietario via API

El model extraction —también llamado model stealing— es el ataque mediante el cual un adversario construye un modelo sustituto que aproxima el comportamiento del modelo target consultando sistemáticamente su API pública, sin acceso a los pesos ni al proceso de entrenamiento original. Para un AI Engineer que ha invertido semanas en fine-tuning un modelo sobre datos propietarios, o para una organización cuyo modelo personalizado representa un activo de propiedad intelectual significativo, model extraction es un riesgo real y técnicamente viable. La distinción entre model extraction malicioso y distillation legítima —la práctica de usar un LLM grande para generar datos de entrenamiento de un modelo más pequeño— es puramente legal, no técnica: desde la perspectiva del proveedor del modelo, los patrones de query son idénticos.

El paper seminal de Tramèr et al. (2016) "Stealing Machine Learning Models via Prediction APIs" estableció los fundamentos teóricos del ataque y demostró que modelos comerciales de ML podían reconstruirse con exactitud alta mediante relativamente pocas consultas. Para LLMs, el paradigma de distillation —popularizado por el paper de Stanford que produjo Alpaca usando outputs de GPT-3.5— demostró a escala que un modelo de alta calidad puede producirse entrenando un modelo base de menor escala sobre los outputs de un modelo más grande. Alpaca fue producido con 52,000 pares instrucción-respuesta generados por GPT-3.5, violando los términos de servicio de OpenAI pero demostrando la viabilidad técnica del ataque a un costo de unos cientos de dólares de API usage.

En el contexto práctico de producción, model extraction es particularmente relevante cuando el valor del modelo reside en un comportamiento diferencial respecto al modelo base: un modelo fine-tuned sobre jurisprudencia legal, sobre datos clínicos de una especialidad médica, o sobre el catálogo de productos de un retailer específico tiene un comportamiento diferencial que puede ser aproximado mediante extracción enfocada en ese dominio. El atacante no necesita replicar el modelo completo —solo el subespacio de comportamiento relevante para su caso de uso— lo que reduce dramáticamente el número de queries necesarias para una extracción útil en el dominio de interés. Los modelos fine-tuned son más fácilmente extraíbles en su dominio de especialización que los modelos base generalistas, precisamente porque su comportamiento diferencial es más pronunciado y más fácil de aproximar.

Los proveedores de APIs como OpenAI y Anthropic monitorean patrones de uso que pueden indicar extracción en curso: alta diversidad de inputs que cubren sistemáticamente el espacio de temas del modelo, volumen inusualmente alto para el tier del cliente, y patrones de queries que maximizan la cobertura del comportamiento del modelo en lugar de un caso de uso específico. Los términos de servicio de todos los proveedores principales prohíben explícitamente usar sus outputs para entrenar modelos competidores. El watermarking estadístico de outputs es una técnica emergente que permite a los proveedores detectar si un modelo fue entrenado con sus outputs incluso si el atacante no lo declara.

## Aspectos técnicos

- **Mecanismo de extracción:** el atacante genera un dataset de inputs que cubren el espacio de comportamientos del modelo target, obtiene outputs via API, y entrena un surrogate sobre esos pares input-output — la distillation del Alpaca original usó 52k pares con GPT-3.5.
- **Extracción funcional vs. fidelidad global:** la extracción funcional replica el comportamiento en el dominio de interés del atacante (suficiente para la mayoría de los casos de uso malicioso) con muchas menos queries que la fidelidad global, que busca replicar el comportamiento completo.
- **Detección por el proveedor:** monitoreo de patrones de query anómalos (alta diversidad de inputs, cobertura sistemática de categorías de temas, volumen desproporcionado al tier del cliente); los ToS de OpenAI, Anthropic y Google prohíben explícitamente distillation sin licencia.
- **Text watermarking:** patrones estadísticos insertados en los outputs del modelo que permiten al proveedor verificar si un modelo fue entrenado con sus outputs; técnica activa de investigación implementada experimentalmente por OpenAI y otros proveedores.
- **Mayor vulnerabilidad en modelos fine-tuned:** el comportamiento diferencial de un modelo fine-tuned respecto al modelo base puede extraerse con menos queries que el modelo generalista completo, porque la señal de especialización es más pronunciada y más fácil de aproximar.

> **Nota del Arquitecto:** La defensa más efectiva contra model extraction no es técnica sino económica y operacional: rate limiting agresivo que hace el ataque costoso en tiempo y dinero, monitoreo de patrones de uso anómalos con respuesta proactiva, y la postura de que el valor del sistema propietario reside no solo en el comportamiento del modelo sino en el pipeline de datos, los procesos de actualización continua y el conocimiento del dominio que alimenta cada iteración. Un surrogate que extrae el comportamiento actual del modelo quedará desactualizado en el próximo ciclo de fine-tuning; el pipeline de actualización es el activo más difícil de replicar.

Model extraction es un ataque de propiedad intelectual que los términos de servicio no pueden prevenir técnicamente sin controles operacionales.
