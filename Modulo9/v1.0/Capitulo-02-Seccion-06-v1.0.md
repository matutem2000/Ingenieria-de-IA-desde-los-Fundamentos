# Módulo 9 – Capítulo 02 – Sección 06

## Cierre: prompt injection es el SQL injection de los sistemas de IA

La analogía entre prompt injection y SQL injection no es solo retórica: es una correspondencia estructural que ayuda a entender por qué el problema es tan persistente y por qué las soluciones puramente reactivas son insuficientes. SQL injection devastó aplicaciones web durante los años 2000 porque los developers concatenaban strings de usuario directamente en queries SQL, mezclando datos con instrucciones en el mismo canal sin separación semántica. Los WAFs que bloqueaban palabras como "DROP TABLE" fueron eludidos por obfuscación, fragmentación y codificación alternativa. La solución llegó cuando la industria adoptó prepared statements y parametrización de queries: un mecanismo arquitectónico que el motor de base de datos entiende como límites infranqueables entre código SQL y datos del usuario. El resultado no fue eliminar toda posibilidad de ataque, sino hacer que la inyección a nivel de SQL fuera estructuralmente imposible cuando el mecanismo se usa correctamente.

La prompt injection existe porque los sistemas de IA mezclan instrucciones y datos en el mismo contexto de atención sin separación criptográfica. La solución arquitectónica de largo plazo requerirá mecanismos análogos a los prepared statements: formas de marcar el límite entre instrucciones del sistema y datos del usuario que el modelo no pueda cruzar bajo ninguna circunstancia. Ese mecanismo aún no existe con garantías formales —los separadores estructurales y las instrucciones de refuerzo son mitigaciones efectivas pero no equivalentes a la garantía que proporciona un prepared statement. Hasta que existan y sean ampliamente adoptados, la defensa en profundidad mediante validación de input, separadores estructurales, modelos de clasificación especializados y privilege separation es el estándar operacional de la industria.

Lo que el paralelismo con SQL injection enseña pedagógicamente es la inevitabilidad de la madurez del ecosistema. En 2003, las vulnerabilidades de SQL injection eran consideradas problemas de "programadores descuidados". Hoy son consideradas fallas de arquitectura del sistema, y ningún framework moderno de desarrollo web permite concatenar user input en queries SQL sin mecanismos de protección. En 2025, la prompt injection es todavía parcialmente "problema de diseñadores descuidados"; en unos años, los frameworks de LLM application que no implementen separación estructural por defecto serán considerados tan inseguros como los frameworks web sin parametrización de queries.

La hoja de ruta para el lector que construye sistemas de IA en producción es clara: implementar ahora la defensa en profundidad disponible (LlamaGuard, separadores, instrucciones de refuerzo, privilege separation), mantener seguimiento de la evolución de los mecanismos de separación estructural en los proveedores de modelos, y participar en la comunidad de security research en IA para que las soluciones arquitectónicas de largo plazo sean desarrolladas, adoptadas y estandarizadas con la urgencia que la prevalencia del ataque demanda.

## Conceptos clave del capítulo

- **Prompt injection directa:** el usuario inyecta instrucciones en su input para sobrescribir el system prompt; mitigada con instrucciones de refuerzo, separadores estructurales y separación de roles en la API del modelo.
- **Prompt injection indirecta:** instrucciones maliciosas en documentos RAG, páginas web o emails que el agente procesa como contexto confiable; mitigada tratando todos los datos externos como untrusted y validando outputs antes de ejecutar acciones.
- **Jailbreaking:** técnicas narrativas, de roleplay, many-shot y gradual escalation para eludir restricciones del modelo sin inyección directa; requiere validación semántica del output independiente del modelo.
- **Prompt leaking:** extracción del system prompt confidencial mediante requests directos, roleplay o tool calling; mitigada no incluyendo credenciales en el system prompt y detectando el texto del prompt en los outputs.
- **Defensa multicapa:** LlamaGuard + Prompt Guard en el input, separadores estructurales y instrucciones de refuerzo en el prompt, output validation con judge model, y privilege separation en el plano de acción es el stack mínimo de defensa.

*"The most dangerous code in the world is the code that handles attacker-controlled input."* — Michal Zalewski (lcamtuf), investigador de seguridad y autor de "The Tangled Web", resumiendo el principio que unifica SQL injection, XSS y prompt injection como instancias del mismo problema fundamental: la mezcla de datos y código en el mismo canal de comunicación.
