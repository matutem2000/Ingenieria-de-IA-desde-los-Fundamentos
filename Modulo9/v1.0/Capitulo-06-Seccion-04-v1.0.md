## Differential privacy en fine-tuning: técnicas para proteger datos de entrenamiento sensibles

Differential Privacy (DP) es el framework matemático que proporciona la única garantía formal y cuantificable sobre la privacidad de los datos de entrenamiento: dado un parámetro epsilon (el presupuesto de privacidad), DP garantiza matemáticamente que la probabilidad de que un adversario pueda inferir si un dato específico estuvo en el training set está acotada, independientemente del poder computacional del adversario y de cuánta información tenga sobre el modelo. Esta garantía matemática es cualitativamente diferente a cualquier promesa basada en buenas prácticas: no es "hicimos nuestro mejor esfuerzo para proteger los datos" sino "matemáticamente, la información que el modelo puede revelar sobre cualquier ejemplo individual está acotada por epsilon".

DP-SGD (Differentially Private Stochastic Gradient Descent), propuesto por Abadi et al. en 2016 y popularizado por la librería Opacus de Meta (open-source, compatible con PyTorch), es el algoritmo estándar para implementar differential privacy durante el entrenamiento de modelos de deep learning. El mecanismo de DP-SGD opera en dos pasos que se aplican en cada batch del gradiente descent: primero, gradient clipping, que limita la norma del gradiente de cada ejemplo individual a un valor máximo C (por defecto C=1.0 en Opacus), reduciendo la influencia máxima que cualquier ejemplo individual puede tener sobre los pesos del modelo; segundo, adición de ruido gaussiano calibrado al presupuesto epsilon y a C, que introduce incertidumbre suficiente para garantizar que el modelo no puede revelar si cualquier ejemplo específico estuvo en el training set con probabilidad mayor a la garantizada por epsilon.

El trade-off fundamental de DP entre privacidad y utilidad del modelo es el aspecto más importante para el AI Engineer que debe decidir si implementarlo y con qué parámetros. Un epsilon pequeño (epsilon < 1.0, considerado "privacidad fuerte") añade suficiente ruido para que la degradación en accuracy del modelo sea significativa —típicamente 3-8% de degradación para modelos medianos entrenados con datasets de fine-tuning de tamaño moderado. Un epsilon mayor (epsilon = 8-10) proporciona protección mucho más débil matemáticamente pero degrada la accuracy menos. La elección correcta de epsilon depende de la sensibilidad de los datos: para datos de salud o datos financieros de alta sensibilidad, epsilon < 1.0 puede ser la única opción éticamente justificable; para datos de menor sensibilidad, epsilon = 8 puede proporcionar protección suficiente con menor degradación de calidad.

La combinación de PEFT (Parameter-Efficient Fine-Tuning) con DP-SGD —específicamente LoRA (Low-Rank Adaptation) con Opacus— ha emergido como la práctica más efectiva para fine-tuning de LLMs con privacidad: LoRA reduce el número de parámetros sujetos a entrenamiento (y por tanto al ruido de DP) a menos del 1% de los parámetros totales del modelo, lo que reduce drásticamente la degradación causada por el ruido diferencial mientras mantiene la utilidad del fine-tuning. Un sistema que hace fine-tuning de Llama-3 o Mistral sobre datos de usuarios con LoRA + DP-SGD puede mantener epsilon = 3-5 con degradación de calidad inferior al 2%, un trade-off operacionalmente aceptable para la mayoría de los casos de uso con datos sensibles.

## Aspectos técnicos

- **DP-SGD con Opacus (Meta, open-source):** gradient clipping (norma máxima por ejemplo C=1.0) + adición de ruido gaussiano calibrado a epsilon y delta; compatible con la mayoría de arquitecturas de Transformers; requiere wrapping del optimizador de PyTorch con `PrivacyEngine`.
- **Presupuesto de privacidad (epsilon):** epsilon < 1.0 = privacidad fuerte (recomendado para PHI o datos financieros de alta sensibilidad), epsilon 1-10 = privacidad moderada (suficiente para la mayoría de aplicaciones con datos sensibles), epsilon > 10 = protección matemática débil; el valor de epsilon debe documentarse en el design document del sistema.
- **LoRA + DP-SGD:** combinar fine-tuning con LoRA (solo ~0.1-1% de parámetros entrenados) con DP-SGD reduce la degradación de accuracy porque el ruido afecta menos parámetros; práctica recomendada para fine-tuning de LLMs grandes con datos sensibles.
- **Privacy accounting:** el presupuesto epsilon se "consume" con cada paso de entrenamiento; Opacus implementa privacy accounting automático con Rényi DP para calcular el epsilon total consumido; el accounting debe verificarse al final del entrenamiento antes del deployment.
- **Alternativas a DP-SGD:** federated learning con aggregación segura para entrenar sobre datos distribuidos sin centralizar los datos; generación de datos sintéticos con generadores diferencialmente privados para crear datasets que preservan propiedades estadísticas sin PII.

> **Nota del Arquitecto:** Differential privacy suena a "investigación académica" hasta que un regulador de GDPR pregunta cómo puedes garantizar que el modelo no puede revelar datos personales de las personas cuya información usaste para entrenarlo. En ese momento, "hicimos anonimización básica" no es una respuesta suficiente; DP es la única respuesta con respaldo matemático. He implementado DP-SGD con Opacus en producción y el trade-off real en accuracy para epsilon = 5-8 con LoRA es menor de lo que los papers académicos sugieren —típicamente 1-3% en tareas de clasificación y NLU, mucho menos que el costo de un incidente de privacidad.

Differential privacy es la única técnica que proporciona garantías matemáticas cuantificables sobre la privacidad del training data; para sistemas que procesan datos de salud, datos financieros o cualquier categoría de datos de alta sensibilidad, la implementación de DP-SGD con epsilon documentado no es opcional sino el requisito técnico mínimo que puede sostener una auditoría regulatoria de privacidad.
