# GDPR aplicado a sistemas de IA: base legal, minimización y derecho al olvido

El GDPR (Reglamento General de Protección de Datos, en vigor desde mayo 2018) aplica a los sistemas de IA siempre que procesen datos personales de personas en la UE o EEE, lo que incluye prácticamente cualquier sistema de IA conversacional, sistema RAG con documentos de clientes, o sistema de fine-tuning con datos de usuarios. Las tres áreas de mayor complejidad técnica del GDPR aplicadas a IA son: (1) la base legal para el procesamiento (el consentimiento informado para usar los datos del usuario en fine-tuning es significativamente más alto que para inferencia), (2) la minimización de datos (solo recolectar y procesar el mínimo de datos necesario para la finalidad declarada — tensión directa con la tendencia a logear todo para mejorar el modelo), y (3) el derecho al olvido (Art. 17 GDPR exige borrar todos los datos de un usuario cuando lo solicita, incluyendo datos en logs de inferencia, vectorstores personalizados, y modelos fine-tuned con sus datos). La implementación técnica del derecho al olvido en sistemas de IA con modelos fine-tuned es el desafío más complejo: la técnica de machine unlearning —eliminar la influencia de datos específicos del modelo entrenado sin reentrenar desde cero— está en estado de investigación activa.

## Aspectos técnicos

- Base legal para procesamiento en sistemas de IA: el Art. 6 GDPR exige una base legal para cada operación de procesamiento; la inferencia de un LLM sobre datos del usuario puede tener como base el contrato (necesario para prestar el servicio) o el interés legítimo; el fine-tuning del modelo con datos de usuarios generalmente requiere consentimiento explícito e informado (Art. 7), que debe ser granular y revocable
- Minimización de datos en el logging de inferencia: el principio de minimización (Art. 5.1.c) exige que los logs no contengan más datos personales de los necesarios para la finalidad declarada; un log de inferencia que almacena el texto completo del input del usuario indefinidamente viola minimización si la finalidad es solo seguridad; solución: almacenar hash del input + metadata de seguridad, con el texto completo cifrado por usuario con TTL de 90 días
- Derecho al olvido (Art. 17): cuando un usuario solicita borrado, el sistema debe eliminar sus datos de: logs de inferencia (borrado selectivo o descifrado de la clave de usuario), historial de conversación, documentos personales en el vectorstore, y datos de fine-tuning — la DSAR (Data Subject Access Request) debe procesarse en 30 días
- Machine unlearning: técnica para "desaprender" el efecto de datos específicos de un modelo entrenado sin reentrenarlo desde cero; aproximaciones actuales incluyen gradient ascent sobre los datos a olvidar (SISA training), influence function-based unlearning (costoso computacionalmente), y approximate unlearning methods; ninguna es perfecta, y para datos altamente sensibles, el enfoque más pragmático es reentrenamiento completo excluyendo los datos del usuario que solicitó el olvido
- Transferencias internacionales: si los datos de usuarios de la UE son procesados en servidores de AWS en us-east-1, la transferencia internacional requiere mecanismos legales como Standard Contractual Clauses (SCCs) o certificación bajo el EU-US Data Privacy Framework

## Para recordar

El GDPR aplicado a sistemas de IA requiere que el equipo de ingeniería tome decisiones de diseño que serían innecesarias si no hubiera datos personales: arquitectura de borrado selectivo en logs, gestión de consentimiento para fine-tuning, machine unlearning para el derecho al olvido, y minimización activa de la retención de PII en todas las capas del sistema.
